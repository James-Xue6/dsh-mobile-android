## 零、实测结论速查（针对**工作区当前源码 `src/`**）

| 项 | 判定 |
|---|---|
| happy path（配对→token 重连→订阅→发消息→流式 chunk→审批→提问→文件下载 208 块/sha256 通过→turn/end） | ✅ 通（协议错误 0） |
| P0-1 假连接（`--fault silent`） | ✅ 生效（实测 75.0s 判死，`close(1011)`，随后自动重连成功） |
| 握手看门狗（`--fault nohello`） | ✅ 生效（实测 10.01~10.77s，`close(1000,"握手超时")`，退避 1s→3s→6s） |
| P1-2 热重连（`--fault emptyclose`） | ✅ 生效（退避递增 **3s→12s→51s**，40s 内仅 3 次，旧的 12 次恒定 1.6s 已消失） |
| `session-stream-reset`（`resetstream` / `retrytrue` / `retryfalse`） | ✅ net 层三条分支全部实测（含 `retrying:true` 续流恢复） |
| 服务端主动关闭**语义码**（`--fault close4003` / `close4004`） | ✅ 生效（4003→UNAUTHORIZED、4004→GATEWAY_OFF，均停止重连；**本轮新修**） |
| P1-4 503 停止重连 + 文案（`--fault gatewayoff`） | ✅ 生效（40s 内 1 次重连、间隔 300s；GATEWAY_OFF 不再被 DISCONNECTED 覆盖） |
| 协议版本校验（`proto4`）/ 能力校验（`nocaps`） | ❌ **未实现**（照单全收、无提示；如实记录，非回归） |
| UI 层全部（气泡/文案/按钮/看门狗/审批卡渲染/安装链路） | ⚠️ **[未验证]**（模拟器在 DSH 会话里起不来） |

## 一、两条测试路线，选哪条

| 路线 | 要不要模拟器 | 能验什么 | 命令 |
|---|---|---|---|
| **A. JVM harness + 假网关** | ❌ 不要 | 网络层全部逻辑：配对、token 重连、订阅、发消息、流式、审批、提问、文件下载、12 档故障下的重连/超时/退避/关闭码 | `node tools/run-e2e.mjs` |
| **B. 模拟器 + 装机** | ✅ 要 | UI、扫码、输入法、锁屏/后台、真机安装链路 | `tools\启动模拟器并装机.bat` |

**路线 A 是主力**：它复用 App 真实的 `net/WsClient.java` + `net/GatewayClient.java` 源码在 JVM 上跑，
不是另写一份模拟实现 —— 所以网络层的行为结论可以直接代表 App 的行为。
**但它验不了 UI**：`MainActivity` / `ConversationView` / `Adapter` 都没进 harness（需要真机或模拟器）。

## 二、路线 A：一键跑端到端 + 故障注入 + 逐档判定

```powershell
cd F:\AI\程序开发\dsh-mobile-android

# 1) 编译 harness（默认 = 工作区当前源码 src/ -> harness/out）
pwsh -NoProfile -File harness\build.ps1

#    需要拿冻结快照做新旧对照时（输出 -> harness/out-ce7afd8）：
# pwsh -NoProfile -File harness\build.ps1 -NetRoot harness/snapshot/ce7afd8

# 2) 跑全部 12 档（none + 11 故障），约 9.5 分钟
node tools\run-e2e.mjs --port 3191

#    只跑某几档 / 调时长 / 换端口
node tools\run-e2e.mjs --fault silent --maxms 120000 --port 3191
node tools\run-e2e.mjs --fault none,silent,nohello --port 3191
node tools\run-e2e.mjs --fault none --classdir harness/out-ce7afd8   # 用快照产物跑同一套用例

# 3) 逐档「可判定结论」分析（读 last-run.json + 每档 mock-gateway.jsonl / harness.log）
node tools\e2e-assert.mjs
```

产物：
- `tools/runs/<fault>-<时间戳>/mock-gateway.jsonl` —— **mock 侧记录的真实帧**（含每次 close 的方向/码/原因）★ 关键证据
- `tools/runs/<fault>-<时间戳>/gateway.log` —— 网关侧屏幕输出（含每帧 JSON）
- `tools/runs/<fault>-<时间戳>/harness.log` —— App 侧（net 层）每个状态变化
- `tools/logs/<fault>.summary.txt` —— 每档摘要（含本次用的 `classDir`，用于自证"测的是哪份代码"）
- `tools/logs/last-run.json` —— 最近一次运行的 档位→runDir/exit/classDir 映射

### 12 档故障

| 档位 | 注入什么 | 想验的修复 |
|---|---|---|
| `none` | 正常全链路 | happy path 是否通 |
| `nohello` | 升级成功但**不发 hello**（仍回 pong / 发帧） | 10s 握手看门狗 + 退避递增 |
| `silent` | 发 hello 后**完全静默**（不回 pong、不应答） | 假连接 75s 主动断开重连（P0-1），close 码 1011 |
| `emptyclose` | 每 1.5s 发一个**空 close 帧** | 重连退避是否正常增长（P1-2，不是 1.6s 热循环） |
| `resetstream` | 流到一半发 `session-stream-reset`（**不带** `retrying` 字段） | 缺省=false 的兼容路径 |
| `retrytrue` | 同上，但帧带 `retrying:true`，随后 mock 补发续流 | `retrying:true` 是瞬时中断，不该按终态处理 |
| `retryfalse` | 同上，帧带 `retrying:false` | `retrying:false` 才是终态、不续流 |
| `proto4` | `hello.protocol=4` | 有没有协议版本校验（P1-16） |
| `nocaps` | `hello.capabilities` 只剩一项 | 能力缺失时有没有提示（P1-16） |
| `gatewayoff` | HTTP 503 拒绝升级 | 是否停止无脑重连并给明确文案（P1-4） |
| `close4003` | hello 后服务端主动 `close(4003,"authentication enabled")` | App 能否读到语义码、停止重连并要求重新配对 |
| `close4004` | hello 后服务端主动 `close(4004,"mobile gateway disabled")` | 能否进 GATEWAY_OFF 而不是无限重连 |

> `4003`/`4004` 不是编造的：真实网关就是这么关的
> （`dsh-plugin-mobile-gateway/lib/index.mjs:2742 / 2788 / 2280`）。

## 三、路线 B：模拟器 + 装机（在你的桌面会话里跑）

```powershell
# 双击即可（起 AVD → 等开机 → adb install -r → 打开 App）
tools\启动模拟器并装机.bat

# 或带参数
pwsh -NoProfile -ExecutionPolicy Bypass -File tools\启动模拟器并装机.ps1 `
     -Avd dshphone -Apk dist\dsh-mobile.apk -TimeoutSec 600

# 只起模拟器不装机 / 清数据重来 / 无窗口
pwsh ... -File tools\启动模拟器并装机.ps1 -SkipInstall
pwsh ... -File tools\启动模拟器并装机.ps1 -WipeData
pwsh ... -File tools\启动模拟器并装机.ps1 -Headless
```

然后另开一个窗口：

```bat
tools\启动物联网关.bat                 :: 默认 fault=none host=10.0.2.2 port=3191
tools\启动物网关.bat silent            :: 换故障档
tools\启动物网关.bat none 3191 192.168.1.20   :: 真机走局域网时填电脑 IP
```

网关会把配对串打印到屏幕**并写入 `tools\pairing.txt`**，在 App 里粘贴或生成二维码扫描即可。

## 四、踩过的坑（照着做能省时间）

1. **端口 3091 在本机被 DSH 宿主自己占用**（`DeepSeek Harness.exe` 监听 0.0.0.0:3091）。
   所以脚本默认用 **3191**，别再用 3091，会 `EADDRINUSE`。
2. **模拟器里访问本机网关必须用 `10.0.2.2`，不是 `127.0.0.1`**。
   配对串里的 `publicUrl` 是网关按 `--host` 生成的；忘了改就会让 App 去连它自己而永远连不上。
3. **`am start -e pairing <串>` 的自动化注入已失效**（P0-4 后门已在 `ce7afd8` 关掉）。
   明早的自动化只能走"配对串粘贴 / 扫码"。
4. **`harness/build.ps1` 的默认源码根是 `src`（当前代码），默认产物是 `harness/out`。**
   旧版本默认编 `harness/snapshot/ce7afd8` 并把产物写成 `out-ce7afd8`，而 `run-e2e.mjs`
   又把 `classDir` **硬编码**成 `out-ce7afd8` —— 于是"用默认链路跑出来的结论测的是旧快照"，
   结论无效。两处默认值本轮都已改为当前源码；`-NetRoot harness/snapshot/<sha>` 仍可用于新旧对照。
   同理，脚本注释里的 `-NetRoot ..\src` 也是错的（会解析到仓库**上级**的 `src`），正确写法 `-NetRoot src`。
5. **`harness/out` 会被 `build.ps1` 整目录删除重建**：不要在同一时间并行跑
   "编译"与"跑 e2e"，否则会撞 `ClassNotFoundException: Harness`。需要并行时用
   `--classdir harness/out-<别的名字>`。
6. `mock-gateway.mjs` 是从评审报告 task-4 的原文落盘的，但**原文有两处必须修**（已在文件里用
   `[落盘修复①/②]` 注释标出），另有 4 处 `[落盘增补]` 是为了能真跑起来加的：
   - 修复①：`onMsg(m)` 无接收者调用 → `this` 为 undefined → 第一帧就把 node 打死
   - 修复②：`--fault silent` 原文是**空档**（什么都不掐），假连接根本验不到
   - 增补③：`--host`（配对串里的主机名）
   - 增补④：把配对串写进 `pairing.txt`

## 五、跑不了 / 验不到的部分

- **模拟器在 DSH 会话里起不来**：AVD、AEHD、QEMU 都能起来并打印 `AEHD is operational`，
  但随后静默退出（exit code `0xFFFF7001`）；开/关硬件加速都一样，无 WER 崩溃记录。
  三种绕法（直调 QEMU、`-no-accel`、`schtasks` 脱离沙箱进程树）均失败。
  → **所以 UI 层结论全部是"未验证"**，只能在你的桌面会话里跑路线 B。
- **harness 只覆盖 net 层**：`MainActivity` 里的 30s 发送看门狗、`setRunning` 复位、
  审批卡"未发送"文案、`registerDefaultNetworkCallback`、`onStreamReset` 的 UI 分流（摘气泡/轻提示）
  等，都需要真机/模拟器。
- **本地没有真实网关**：全部结论来自 mock 网关。`session-stream-reset` 的 `retrying` 字段
  取值以真实网关（`lib/index.mjs`）为准，本轮已按真实字段名 `retrying`（顶层布尔）注入复验。
