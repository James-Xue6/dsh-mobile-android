## 八、追加（2026-10-08 · 另一会话）圆角红线修复：`radius = 999.dp` 已废止

**用户报障**：「我开大圆角然后你弄得假背景就出来了，背景为啥也直接变形虚化了！！」
（当时前台是 `com.dsh.mobile/.glass.GlassChatPageActivity`）

**根因（已在模拟器复现对照）**：调用处用了 `radius = 999.dp` 当"胶囊圆角"。
`radius` 的**硬上限 = 短边/2**；超过后圆角矩形退化成极限态，**形状不再覆盖玻璃节点**，
模糊/折射外溢到整块节点矩形 → 旁观就是"玻璃外面的背景也被虚化/变形"（背景图层本身没被改）。
对照：半径 26dp 时背景锐利；半径 90dp（>短边/2，56dp 胶囊即 >28dp）时周围出现柔化区。

**已做（本轮，已编译 + 模拟器验证）**
1. `RefractionWindow.kt` 新增 `BoxWithConstraints` **自动夹取 radius ≤ 短边/2** —— 调用处写多大都安全；
2. `RefractionWindow.kt` 新增 **`RefractionCapsule()`** —— 胶囊专用入口，圆角自动 = 短边/2，高度改了也不失效；
3. 两个调用处改为 `RefractionCapsule()`：
   - `GlassChatPageActivity.kt` 输入胶囊（原 `radius = 999.dp`）
   - `GlassDevicePageActivity.kt` 添加设备胶囊（原 `radius = 999.dp`）
4. 证据：`液态玻璃引擎Demo\shots\user_chatpage_fixed.png`、`user_devicepage_fixed.png`
   （两页的胶囊形态正确，且胶囊周围的极光/星空**未被虚化**）

**规范同步**：`GlassUI_SPEC_折射观察窗.md` 新增 **§7.6 圆角红线**、§6 踩坑表新增一行、§7.2 圆角行改为"0 → 短边/2（硬上限）"。

**给下一个执行者的两条硬性要求**
- **装配胶囊一律用 `RefractionCapsule()`**（本文档 §三 的装配式样里若还写着 999，以本条为准）；
- 方形/卡片件圆角 **≤45% 短边**（保留四角），且永远不要超过短边/2。

## 十、追加（2026-10-08 · V1.9.1）「白线跟着玻璃跑」= 白棱过强

**报告**：`docs/GlassUI/GlassUI_Report_V1.9.1.md`

- **定性（量化，非目测）**：背景白网格线在玻璃内**是直的**（横带偏移仅 +1~+2px = 不被拖弯）；
  真正的问题是玻璃自身的棱 —— 反推等效白度：Compose **≈60%**，而正式版 `FrostedPanelView`
  的 `hairline(0x1EFFFFFF)` 只有 **≈12%**，**强约 5 倍**。背景换成正式版低频配色底后，
  屏幕上唯一像"线"的就只剩它 → 观感成了"白线沿玻璃形状跑"。
- **改动（1 个质感数值）**：`RefractionWindowTokens.HighlightAlpha = 0.35f`，
  `highlight = { Highlight.Default.copy(alpha = 0.35f) }`。`width/blurRadius` 未动（错的是亮度不是宽度）。
  **0.20 试过被用户否掉**（「受光边变弱了这么多，加强点」）→ 三档对照后定 **0.35**（等效白 ≈0.51；
  默认 ≈0.86 太强像描边、0.20 ≈0.39 丢受光）。
- **证据**：`evidence/v190/62_abc_evidence.png`、`63_abc_devcard.png`（三档并排放大，定档主证据）；
  `60/61_*_h35.png` 最终整屏；棱峰 默认 235 → 0.20 171 → **0.35 187**（取证页 y=950）。
- **⚠️ 规范 §1.1 写的是"Highlight 用官方默认"，本次属受控偏离 → 需用户签字后回写规范**（与 §五.5 那三条一起）。
  再微调：更明显 → `0.45f`；再收 → `0.30f`。
- **踩坑记录（已进错题本）**：`Highlight.alpha` 与"等效白度"**不是线性对应**，且同一 alpha 在深底/浅底
  两页上表现差很多 —— **定档必须看并排观感，不能只看单一数字**。

## 十一、追加（2026-10-08 · V1.9.2）「一动就变」= 水波纹在方角节点上画的灰方块

**报告**：`docs/GlassUI/GlassUI_Report_V1.9.2.md`

- **现象**：静止帧好看，**一按下**就冒方块 —— 按住「＋ 添加设备」玻璃胶囊 → 胶囊内部出现
  **深灰方角矩形**；按住右上角玻璃圆齿轮 → 圆外出现**灰色方块**。
  证据：`evidence/v190/91_gear_pressed.png`、`92_addcard_pressed.png`、`104_addcard_abc.png`（三格）。
- **根因（架构层，调参无解）**：`Modifier.clickable` 默认带 Material `indication`（水波纹），
  它画在**节点的矩形边界**上；而玻璃圆角是 `drawBackdrop(shape=…)` 在**绘制期**画的，
  **布局期节点仍是方角** ⇒ ripple 露出方角灰块。
- **正式版口径**：全程用 `Ui.tap(v, 0.98f)`（按下缩到 0.98），**没有水波纹** → 是我引入的偏差。
- **修复**：新增 `Modifier.glassTap(scale, onClick)`（`indication = null` + 按下缩放 0.98），
  替换设备页 3 处裸 `clickable`（齿轮 / 添加卡整体 / 三按钮挂整只胶囊）。
  按下时变化像素：添加卡 **59826 → 4692**、齿轮 **→ 319**、按钮 **→ 1011**（残留即 0.98 缩放）。
- **🔒 新硬规则（建议回写规范）**：**本工程 Compose 侧玻璃件一律用 `Modifier.glassTap { }`，
  禁止裸 `Modifier.clickable`**（任何按节点边界绘制的 indication 都会露方角）。

## 十七、追加（2026-10-08 · V3.2）对话页重做：内容进取样层 + 底部三件式

**报告**：`docs/GlassUI/GlassUI_Report_V3.2.md`

**用户反馈**：上下应是独立玻璃胶囊；「对话胶囊滑上去**没有玻璃质感**」；底部不要大长条，
要「左圆玻璃＋ / 中间圆角长条输入条 / 右圆↑」三件，**滚动内容要在玻璃里发生形变**；顶面同样。

### 17.1 根因（重要，别再犯）
上一版 `layerBackdrop` **只铺在背景上**，滚动内容在**层外** ⇒ 玻璃永远只糊到平滑渐变，
内容滑过时既不被糊也不被推开 → 看着"没有玻璃质感"。
**修法：取样层 = 环境背景 + 可滚动内容；玻璃件一律留在层外**（否则自取样）。
> 正式版同理：`FrostedPanelView` 的抓取源是**列表容器**，所以滚过时顶栏/输入条里能看到糊掉的消息。

### 17.2 结构规则（后续每屏照此判断）
| 内容类型 | 放在哪 | 用什么画 |
|---|---|---|
| 滚动内容（消息/列表） | **取样层内** | **半透明卡**（= 正式版 `Ui.GLASS_CARD`：浅色白 26% / 深色 `#14121C` 30% + 发丝线） |
| 悬浮件（顶栏 / 输入条 / 圆形钮 / 入口胶囊） | **取样层外**（同页最外层 Box） | **真玻璃**（RefractionWindow / RefractionCapsule） |

⚠️ **规则**：**取样层里不要放假玻璃**（自取样 → 鬼影）；**悬浮件不要放进取样层**。

### 17.3 底部布局（用户定版）
去掉整条磨砂板 → **三个独立玻璃件**：左圆「＋」38dp / 中间圆角 22dp 输入条 46dp / 右圆「↑」38dp
（品牌实心 88%）；「N 子智能体」入口改成独立玻璃胶囊（正式版 N=0 时不显示）。

### 17.4 验证
滚动一次后：**顶栏玻璃区变化 50821/162000 像素、底部三件区 59201/172800**（玻璃确实在跟着内容糊）；
真机 `evidence/v320/11_real_chat_scrolled.png`：顶栏背后文字被糊、输入条里是糊掉的「交付物 / GlassUI…」。
release 已装机、无新崩溃（dropbox 最后一条仍停在 21:22:47）。

## 二十八、追加（2026-10-08 · V3.9.4）抽屉那条边 **修好了**（真因：背景按 padding 盒绘制）

**报告**：`docs/GlassUI/GlassUI_Report_V3.9.4.md`（A 类质感改动 = 0，只改容器结构）

- **真因**：V3.5 给外壳加的 `DrawerHost.applySafeInsets()` → `drawer.setPadding(0,top,0,bottom)`，
  而 **View 的背景是按 padding 盒绘制的** ⇒ 挂在 `drawer` 上的玻璃底（模糊玻璃 + 斜射高光 + 右缘发丝线）
  被裁短/错位 ⇒ 面板内部多出一圈"边"、右缘像"硬切没棱线"。
  （代码里 2026-10-03 记过同类现象："elevation 阴影从半透明体下透出，在面板内画出**一圈灰环**"。）
- **修法（3 处）**：① 新增 `private final View bg`（玻璃底独立子 View，elevation=0）；
  ② 构造顺序改为 建 drawer → 建/加 bg → 加 drawer（`drawer.setBackground(null)`）→ **最后** `applyDrawerBg()`，
  且 `applyDrawerBg()` 把 LayerDrawable 设到 **bg** 上；③ `onMeasure` 让 bg 与 drawer **同宽**，`applyTx` 两者一起平移。
- ⚠️ **踩坑**：第一版把 `applyDrawerBg()` 留在原位（早于 bg 赋值）⇒ 运行期 **NPE**，点开抽屉即闪退。已修。
- **验收（模拟器）**：`evidence/v394/02_drawer_glassfix.png` + `crop_top2.png` —— 圆角描边消失、
  右缘恢复棱线、内容正常、无崩溃（`mCurrentFocus` = MainActivity）。
- 真机仍卡安装确认框（第 8 次）；`lastUpdateTime` 仍 23:24:51 ⇒ 需用户点一次「继续」。

## 四十一、追加（2026-10-09 · V3.20+V3.21）模拟器配方纠正 + §6 第 1 条前半落地

**报告**：`docs/GlassUI/GlassUI_Report_V3.20.md`、`V3.21.md`（**A 类质感数值改动 = 0**）

### 41.1 ⚠️ 模拟器配方（我这次走错的坑，已写死进《换会话交接》§8）
- ❌ 用 `F:\...\android-sdk\emulator\emulator.exe`（或自造 AVD）⇒ 写 `C:\Users\Administrator\.android\*.lock` 报
  `error 5` → **无限重试自旋**：日志暴涨、客户机 CPU 冻在 0.4s、adb 永不注册。
- ✅ 正解：`C:\Users\Administrator\emu_copy\emulator\emulator.exe -avd Pixel_7_API35 -no-snapshot -gpu host`
  ＋ adb 用 `emu_copy\adb\adb.exe` 且 **`TEMP/TMP=F:\AI\程序开发\.tmp`**；**不要** `-no-window`/`-gpu off`。
  实测 **30s** `boot_completed=1`。原始排障：`_dsh-mobile-evidence/emulator10/README-结论.md`。

### 41.2 ⭐ 机制发现（比本轮改动更值钱，必须记住）
> **Material3 默认行高固定 24sp，只改 `fontSize` 不改行高。**

实测：15.5sp 标题与 11.5sp 说明**都是一行 24dp**。所以"等比例缩小弹窗"若只缩字号 → **高度一点不降**；
只缩 padding/圆角 → 只降约 10%。**必须把行高一起缩。**

### 41.3 ⭐⭐ 真根因：面板一直是"**整屏高**"的（用户"框大"就出在这）
> `RefractionWindow` 内部是 `BoxWithConstraints(modifier) { Box(Modifier.fillMaxSize()) }` ——
> **父级高度约束有界时，内层 `fillMaxSize()` 会撑满整屏** ⇒ 面板其实是"整屏高的玻璃面"，
> 内容只是被 `contentAlignment = Center` **垂直居中**。**通栏时看不出来，一加左右内缩就暴露成整屏高的玻璃柱。**

- ✅ 修法（调用处，不动组件内部）：`modifier = Modifier.fillMaxWidth().wrapContentHeight(unbounded = true)`
  （子级高度无界 ⇒ `fillMaxSize()` 对高度失效 ⇒ 回到内容高度）。
- ❌ **`Modifier.fillMaxWidth(0.8f)` 不能用**：宽度变有限后同样触发撑满（`evidence/v3250/18_F_sheet.png` 故障现场）。
- ❌ **`Modifier.height(IntrinsicSize.Min)` 不能用**：`BoxWithConstraints` 是 SubcomposeLayout，
  查询内在尺寸直接抛 `IllegalStateException` ⇒ **崩溃**（logcat 已取证）。
- ⭐ 另一条必记：**M3 默认行高固定 24sp，只改 `fontSize` 不改行高**（15.5sp 与 11.5sp 实测都是 24dp 行）
  ⇒ 想"等比例缩小弹窗"必须同时给 `lineHeight`，否则高度几乎不动。

### 41.4 §6 第 1 条·前半：添加设备面板整体缩小（已改+已验）
- 用户追加「**左右也缩小**」⇒ 左右各内缩 屏宽×(1−K)/2（用 `padding(horizontal = maxWidth*(1-SheetK)/2)`）。
- `GlassSheet.kt` 单一系数 **`SheetK = 0.8f`**（管内部尺寸、行高、左右内缩）；**全局字号 `Ui.S_*` 一行未动**
  （遵守 `Ui.java:3115`「字号归全局类型比例管」）；按钮触控下限 40dp。
- **实测（411×914dp 屏）**：`411dp 通栏 × 整屏高` → **`329dp（左右各 41dp） × 241.1dp（内容高度、贴底居中）`**。
- 侧边阴影复检：卡片外仅差 3 级亮度 ⇒ **V3.15 的"两侧阴影冒充边框"未复发**，无需给组件加 `shadow` 开关。
