## 6. 追加 V4.00b：行内代码对比度（子智能体/长文本页特别明显）

**现象**（用户截图）：正文里成片的行内代码（`request` / `mgw/*` / `apply`…）是**浅紫色**，
压在很浅的底上 → 「一堆白字看不清」。

**根因**：`MarkdownText.inlineMarkdown()` 里 `code` 追加用的颜色是 `codeFg`，而调用处把 `brand`
当作 `codeFg` 传进来了（同一个参数还兼任"链接色"）⇒ 代码被染成品牌紫。

**最小 diff**：`code` 的 `SpanStyle(color = codeFg)` → `color = ink`（正文墨色，深浅主题都够对比）；
链接仍用 brand（可点语义）。**未动任何玻璃参数**。

**验收**：编译通过并安装；真机 before/after 截图待补（本报告缺 Fig.2）。

## 7. 追加 V4.00c：头块渐变遮罩（方案 B）

**现象**（同一张截图）：滚动到顶部时正文会穿过悬浮标题卡，卡片附近文字与底色糊成一片。

**方案**：保留"可穿透"的玻璃观感，在头块 `Column` 自身垫一层**竖直渐变**（只动布局/叠层）：
`Ui.BG` 94% → 62% 处 78% → 底部 0%。不新增玻璃件、不改 `GLASS_*` / `RIM_*` / `GRAIN_*`。
因为垫在头块 Column 自身（高度 = 头块实测高度），所以展开/收起目标卡时渐变会跟着长高，不会露缝。

## 8. 追加 V4.00d：子智能体页"只读显示栏" + 撤回顶部渐变

**用户口径（原话）**：「界面和主智能体一样，然后下面的那些选项去掉，然后输入框直接当显示栏显示这些提示，但是不能输入」。

- **旧实现**：只读时在底部浮出一行 `Color.White` 小字（浅底上几乎看不见 = 用户说的「一堆白字」），
  而输入区那一整条是空的（「下面有一块空白」），下方 chip 行也不出现 —— 看起来像界面坏了。
- **新实现**：只读时**占住输入框那条位置**，样式照输入条（圆角 999 + `Ui.CHIP_BG` 半透明 +
  0.5dp 白棱），文字用 `ink` 正文墨色展示只读原因；**不渲染输入框** ⇒ 天然不可输入；
  下方 chip 行只在非只读分支渲染 ⇒ 自动消失。
- **同批撤回**：V4.00c 加的"顶部渐变遮罩"属于**加错位置**（用户要处理的是底部），已整段删除。

未改任何质感 Token（仍是 B 类：布局/叠层）。
