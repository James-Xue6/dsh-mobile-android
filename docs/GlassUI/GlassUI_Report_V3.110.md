## 1. 症状 → 根因（代码级证实）

「同一个功能，一会玻璃、一会半透明」= **两套弹窗实现并存**：

| 走哪套 | 结果 |
|---|---|
| 已有的**玻璃分支**（`glassOptionList` / `showSheetList` / `showSheetForm`）| 玻璃质感 ✓ |
| 还没迁移的**旧实现**（`ModelSheet.showOptions` / `Ui.dialog` / `AlertDialog`）| **半透明面板** ✗ |

我逐个站点扫了一遍，**7 处已有玻璃分支**（思考等级 / 切换项目 / 任务列表 / 权限 / 排队消息 / 生成物面板点击 / ⋯菜单），
**16 处还没有** ⇒ 用户看到的就是这个混合状态。

## 2. 本轮做完的：**迁移基建**（已构建 + 装机）

| 新增 | 作用 |
|---|---|
| `GlassChatView#showSheetConfirm(tag,title,msg,label,danger,Runnable)` | 玻璃**确认**形态的 Java 入口（骨架"主按钮"走 `onPick(0)`，这里挂 `onListPick`）|
| `MainActivity#glassConfirm(...)` | `Ui.dialog().setTitle().setPositiveButton().setNegativeButton()` 的 **drop-in** |
| `MainActivity#glassItems(...)` | `Ui.dialog().setItems(new String[]{...})` 的 **drop-in**（按下标回调）|
| （已有）`glassOptionList(...)` | `ModelSheet.showOptions(...)` 的 drop-in |

三者**都是"玻璃宿主不可用就返回 false"** ⇒ 调用方继续走旧弹窗，**回退路径保留**（与 `GlassUI_SPEC_DIALOG.md` 一致）。
⇒ 剩下每处迁移**只剩 2~3 行**（一个 `if (glassXxx(...)) return;` + 把原回调体原样搬进去）。
