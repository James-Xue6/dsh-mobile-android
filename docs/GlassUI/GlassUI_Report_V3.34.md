全部已修并在模拟器上取证：

| # | 参照 `MessageScrubber` 的做法 | Compose 版原来的做法 | 后果 | 已修? |
|---|---|---|---|---|

## 4. 未验证 / 风险

1. ⏳ **手感（1:1 跟手）与触感**只有在真机上才算数；模拟器只能验"方向/跳准/绘制规格"。
2. ⏳ 真机上 `input` 驱动不了 Compose 手势（既有记录）⇒ 真机复验要靠**手点**。
3. ⚠️ **行为变更（需要你点头）**：拖动中**列表不再实时跟着滚**，改为**抬手跳一次** —— 这是**照参照实现**做的
   （参照就是 `ACTION_UP` 才回调）。如果你更想要"边拖边预览"，说一声，我把两者都留着（拖动中只轻薄滚动、抬手精确定位）。
4. ⚠️ 参照的"选中格在中轴**下 0.5 格**"（`slotY(mid) = centerY + 0.5*step`）被**忠实保留**了；
   如果你觉得选中格应该正好在灰底正中，这是一处可调项（改 `mid` 的取值口径即可），**但会偏离参照**。
5. ⚠️ 演示数据被我加了 2 个回合（`demoItems()`）——只为让刻度尺可测；不影响正式版。

## 6. 踩坑（新增）

1. **`pointerInput` 的 key 决定回调闭包的新旧**：任何在 `detectDragGestures` 回调里要用的**即时值**，
   必须从 `mutableStateOf` 现读，**不能捕获 `val`**（本轮 ⑩ 就是这么来的：手势全都"正常"，只是每次跳 `turns[0]`）。
2. **测量脚本的污染源要防三处**：① 环境背景本身就是蓝紫色（会把"紫"判据全中）；② 灰底胶囊**自己的抗锯齿边缘**
   与背景混色也能凑出紫；③ 相邻聊天气泡是近白色，会把"灰底"的 x 范围带偏。⇒ 结论：**把搜索窗口限制在灰底内部**。
3. 同一个 bug 在参照实现里有注释记录（"刻度没在灰底中间、偏右"）——**移植前先把参照的注释读一遍**，
   它写的就是"用户已经骂过的事"。
