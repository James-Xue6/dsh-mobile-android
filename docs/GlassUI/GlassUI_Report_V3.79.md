# GlassUI 迭代报告 V3.79 | 2026-10-11（输出过程中"一直来回跳"：逻辑定位与修复）

> **触发**：用户「还有聊天对话界面为啥**输出过程中一直来回跳**，你看看这个是什么逻辑」。

---

## 1. 为什么会跳 —— 两条逻辑（都是"高度/位置跟着临时状态走"）

### ① 列表顶部让位高度**跟着"临时内容"变**（主因）
`GlassChatScreen.kt` 里列表的 `contentPadding.top` 原本是：

```kotlin
top = maxOf(headDp - planCardPx + 50.dp, headInset) + 2.dp
```

`headDp` 是**头块的实测高度**（`Column(...).onSizeChanged { headPx = it.height }`），而头块里除了目标卡还有两样
**输出期间会反复出现/消失**的东西：

- 「**N 子智能体**」条（子智能体起/停 ⇒ 出现/消失）
- 「**正在加载更早…**」/「已到底」状态行（`moreStatus`）

⇒ 它们一变，`headDp` 就变，让位高度跟着变 ⇒ **整列消息整体上下平移** = 用户看到的"一直来回跳" ✓

### ② 跟随滚动用了"动画"，且每次条目数变化都触发
```kotlin
LaunchedEffect(state.items.size) {
    if (贴底) animateScrollToItem(state.items.lastIndex)
}
```
输出时条目数**频繁增减**（步骤行/工具行不断重建）⇒ `animateScrollToItem` 被反复触发，
**动画叠动画 + 回弹** ⇒ 观感也是"来回跳" ✓

### ③（附带）遗留诊断放大抖动
`LaunchedEffect(headDp.value) { state.debugHead = ... }`（V3.57 临时诊断）会在**每次头块测量变化**时写一次状态
⇒ 多一轮无谓重组。

## 2. 修复

| # | 改动 | 效果 |
|---|---|---|
| ① | 让位高度改成**常量**：`headInset + 50.dp + (有横幅时 44.dp) + 2.dp` | 临时内容出现/消失**不再推动列表** ⇒ 不跳 ✓（目标卡展开时依旧按设计**浮在消息之上**，不推列表） |
| ② | 跟随滚动改**瞬时** `scrollToItem`（不再 `animateScrollToItem`），且**只在真的贴底时**执行 | 不再动画叠加/回弹 ✓ |
| ③ | 删掉遗留诊断写入 | 少一轮重组 |
