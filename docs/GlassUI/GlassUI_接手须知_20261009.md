## 1. 路线 A 的三条硬规则（违反就出问题，全部有实测证据）

1. **取样层 = 背景 + 可滚动内容**；玻璃件一律留在**层外**。
   层内再放真玻璃会自取样 ⇒ 卡片里看不到背景（"一片平白"）。
2. **层内的内容用半透明卡**（`Ui.GLASS_CARD` 口径：浅色白 26% / 深色 `#14121C` 30% + 发丝边）。
   `sample`：`layerBackdrop(backdrop)` 只录得到**同一组合/同一窗口层**的内容
   ⇒ 独立 `ComposeView`（如 MainActivity 另挂的弹窗）**糊不到页面**，会糊出一层白纱。
3. **弹窗/抽屉这类浮层**：要么渲染在**各自屏的同一棵 Compose 树**里（层外）——
   见 `GlassSheet.kt` 的 `GlassSheetOverlay`；要么沿用旧引擎（`Ui.blurredGlassRoot`，能抓窗口背后）。
   **抽屉外壳**继续用旧引擎玻璃（`DrawerHost.applyDrawerBg`），因为 Compose 取不到层级背后的内容。

## 6. 环境/流程须知（踩过的坑）

- **SOP**：改质感前先加载 skill `glass-ui-sop`；一次 ≤2 个质感数值；**禁止重构** `Frost`/`FrostedPanelView` 本体；
  真机截图是唯一验收标准；每轮出报告并回写交接表。本项目至今 **A 类质感改动 = 0**（只做新页面与调用处）。
- **真机（A7QK023224004563，HONOR PGT-AN10）安装**：`adb install` 会弹系统确认框且**拦截注入触摸**；
  验证过的可行序列是 **`am force-stop com.android.packageinstaller` 后再 `adb install -r`**；
  若仍弹框，只能**人工点一次「继续」**（或打开系统里类似「通过 USB 安装应用」的开关）。
  手机上最后一次成功安装是 **23:24:51（V3.9）**，其后所有改动尚未上机。
- **真机不接受注入点击**（`input tap` 对普通 App 无效，实测多次）⇒ 真机验收要靠"启动即到某屏"的调试钩子。
- **调试钩子**：`--ez glass_force_chat true`、`--ez glass_force_device true`、`--ez glass_force_drawer true`、
  `--ez glass_force_press true`。
- 模拟器：`emulator-5554`，深色用 `cmd uimode night yes|no`；真机 EMUI 拦 adb 强切深色。
- 构建：`JAVA_HOME=…Android Studio\jbr`、`ANDROID_HOME=F:\AI\程序开发\android-sdk`、
  `F:\AI\程序开发\.tools\gradle-9.6.0\bin\gradle.bat :app:assembleDebug :app:assembleRelease`（release 用官方签名，密码在 `keystore.local.ps1`）。
- 单独替换多行代码时，**PowerShell 的 `\r\n` 与替换串的 `\n` 不匹配**会让 `.Replace` 静默失败 ⇒
  用**单行锚点**替换，或用正则 `\r?\n`。
- 批量替换"包装/镜像"方法的调用点时，**必须排除 helper 自身定义**，否则会写成自递归直接崩。
