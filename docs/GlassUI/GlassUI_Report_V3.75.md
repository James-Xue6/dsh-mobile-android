> **触发**：用户「1、左侧加号添加文件/相册/拍照，**选择文件之后没出现**，然后也**没有之前弄得放到输入等待和文字一起发送**；

---

## 1. 🎯 bug 1 的根因（已定位）

| 事实 | 证据 |
|---|---|
| 宿主侧的**暂存流程是好的**：选择器 → `stageAttachment(uri, kind)` → 旧视图 `setPendingAttachments` | `MainActivity:4958/5036`、`GlassChatView:352` |
| 但镜像给 Compose 的**只是一个数字**：`state.setPendingAttachments(list.size())` | `GlassChatView.java:354`（改前） |
| 而 Compose 侧**从来没渲染过这个数字**（只有一个孤立字段） | `GlassChatScreen.kt:118`（改前，无任何引用） |

⇒ **选完文件确实暂存了，只是界面上没有任何东西显示它** ⇒ 用户看到的就是"选了没反应、也不像要跟文字一起发" ✗。

## 2. 修复：镜像改成**附件列表** + 渲染**待发附件条**

| 位置 | 改动 |
|---|---|
| `GlassChatState.pendingAttachments` | `Int`（个数）⇒ **`List<String>`**，每项编码 `kind\u0001uri\u0001name` |
| `GlassChatView.setPendingAttachments` | 把 `PendingAttachment` 列表编码进状态（`uri` 为空时退回 `file://localPath`） |
| `GlassChatScreen` | 输入区上方新增**待发附件条**：图片→解码**缩略图**（失败退回文字块）、文件→显示名字；尾随一句**「将与文字一起发送」** |
| 切片（演示） | `attachPick()` 塞两个演示附件 ⇒ 模拟器上可验证该条 |
