# GlassUI 迭代报告 V3.118 | 2026-10-12（"材质一会好一会坏"统一根因 + 一处修复全站受益）

> **触发**：用户「**修改名称为啥又变回去了，进去再出来又好了？**这啥情况？怎么都在变换，是不是有 bug，
> **你检查下所有玻璃弹窗，是不是都有这个 bug？是不是多个代码重复了**」。

---

## 1. 审计结论：**是**，同一个根因；**是**，有 5 处重复渲染器

### 1.1 根因（一个）

`backdrop` 取样层的**内容是在"绘制阶段"记录的**，而玻璃面板**同一帧**就开始采样 ⇒
**首次打开**那次可能采到"**空 / 上一帧**"的层 ⇒ 材质不对；等到**下一次**打开或界面重绘过（层已记录好）⇒
突然就正常了 ⇒ 用户看到的"**进去再出来又好了**" ✓

同一个根因的两个方向：
| 现象 | 机制 |
|---|---|
| 抽屉 ⋯：第一次好、切走回来**变弱** | 层被 dispose 清空后，宿主读到空 ⇒ 退用兜底层（V3.117 已改成可观察状态，能自愈）|
| 修改名称：第一次**不对**、进去再出来才对 | 层还没记录完 ⇒ 面板已采样（本次修复）|

### 1.2 重复（五处渲染器）

| # | 渲染器 | 取样层 |
|---|---|---|
| 1 | `GlassChatScreen` 的 overlay | 对话页 `backdrop` |
| 2 | `GlassDeviceScreen` 的 overlay | 设备页 `backdrop` |
| 3 | `GlassSettingsScreen` 的 overlay | 设置页 `pageBackdrop` |
| 4 | 抽屉宿主 `createGlassSheetHost` | 聊天页主层 → 抽屉层 |
| 5 | `GlassChatView#showSheet*` | 只写状态，由 1 渲染 |

⇒ 5 个各自管取样，所以"有的地方好、有的地方坏" ✓ 这就是用户说的"**多个代码重复**"。

## 2. 修复：**一处生效，全站受益**

在**共享的** `GlassSheetOverlay` 加"**等 N 帧再画面板**"的开关：

```kotlin
fun GlassSheetOverlay(..., settleFrames: Int = 0)   // 默认 0 = 与改动前逐字一致
```

- 符合规范："共享组件不为单一场景改行为" ⇒ 新参数**默认值等于原行为** ✓
- `settleFrames ≥ 1` 时：面板延后 N 帧开始采样 ⇒ 层已记录完 ⇒ **首次即正确** ✓

**已在全部 4 个真正的渲染点启用 `settleFrames = 2`**（等 2 帧更稳）：
`GlassChatScreen:883`、`GlassDeviceScreen:251`、`GlassSessionList:157`、`GlassSettings:499` ✓
