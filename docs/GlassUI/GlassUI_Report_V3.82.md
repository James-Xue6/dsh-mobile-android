# GlassUI 迭代报告 V3.82 | 2026-10-11（纠正：长按复制是**对话消息** · 交付物只留"打开" · 生成物里选打开/下载）

> **触发（用户纠正）**：「**我让你改的是对话界面长按复制**，怎么成交付物了？！
> 交付物聊天界面**点击就是打开**就行了，具体的**到生成物里面，点击能选下载和打开**就行」。

**我上一轮（V3.80）理解错了需求**：把"长按复制"做成了**交付物行**的按钮 ✗。
本轮按原意纠正。

---

## 1. 对话消息：**长按 = 复制这条消息** ✅

- `GlassChatHost` 新增 `copyText(text)`；`GlassChatView.copyText` **直接在视图里写剪贴板** + toast「已复制这条消息」
  （剪贴板是纯本地能力，不绕宿主接口；上下文取 `legacy.getContext()` —— 本类不是 View）。
- Compose 侧：
  - **用户气泡**：长按 = 复制该条文本（点击不做事，只保留按压反馈）；
  - **助手正文**：长按 = 复制该条文本（点击不做事）。
- 为什么需要它：V3.57 移除了 `SelectionContainer` 之后，"长按选中/复制文本"的能力就没了 ⇒ 这是用户一直在说的那个"长按复制"。

## 2. 交付物：**回到单一动作 —— 点击 = 打开** ✅

撤掉 V3.80 加的两个胶囊按钮（「打开」/「复制路径」）与长按行为；
提示行改成「**点一下打开（下载/复制路径在「生成物」里）**」，把选择权交给生成物面板。

## 3. 生成物面板：点击 **可选「打开 / 下载 / 复制路径」** ✅

`MainActivity` 里玻璃版生成物 sheet 的点击回调原来是"直接打开预览"，现改为**先弹选择**：

| 选项 | 行为 |
|---|---|
| **打开（应用内预览）** | 下到私有预览缓存 → `ArtifactActivity`（页内还有「保存」） |
| **下载到手机** | 直接存进手机「下载」目录 |
| 复制路径 | 写剪贴板 + toast |

面板副标题同步改成「…· 点一下**选打开还是下载**」。（不在会话工作目录内的文件，两个动作都会给出明确原因。）
