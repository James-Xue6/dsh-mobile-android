## 2. 待发附件可删除 ✅（**模拟器实测通过**）

**根因**：宿主的删除**早就实现了**（`MainActivity.onRemoveAttachment(PendingAttachment)`，
旧视图附件条上的 × 一直走它），但 Compose 侧既没画 ×、也没有这条通路 ✗。
**修**：
- `GlassChatHost` 新增 `removeAttachment(index)`；`GlassChatView` 存一份最新 `List<PendingAttachment>`，
  按下标换回对象再交给宿主；
- 附件条每张右上角加 **×**（18dp、圆角、白底）；
- 切片同步实现（演示用）。

**取证（模拟器 · 同一份代码）**：点 ＋ ⇒ 出附件条（「图片」+「设计稿.」+「将与文字一起发送」）✓；
点第一张的 × ⇒ **× 节点 2 → 1、图片块 1 → 0、设计稿块保持 1** ✓✓ **删除生效**。

## 3. 工具行"一直闪烁 / 一会英文一会中文" ✅（根因 + 修复）

**根因（有代码定位）**：`ConversationView.flushStep()`（1612-1692）组装步骤摘要时，
把**工具原始英文名**直接拼在中文标签后面：

```java
names.add(it.toolName == null || it.toolName.isEmpty() ? "工具" : it.toolName);  // ← read / bash / grep…
sb.append(runningLabel(activity(lastRunningTool.toolName)))
  .append(" · ").append(lastRunningTool.toolName) ...                            // ← 「执行了命令 · bash…」
```

⇒ 一行里中英混排 ✓；又因为**每个工具事件都会重写这一行的尾巴** ⇒ 观感就是"一直闪烁" ✓。

**修**：
1. `StepProcess.toolNameCn(raw)`：工具名 → **中文短名**（`read`→读取文件、`bash`→命令行、`grep`→搜索代码…），
   **未知工具也不吐英文**（细节留给工具行展开看）；
2. `flushStep`：**运行中不再带工具名**（那条尾巴是抖动源），完成态若只有一次调用则带**中文名**；
3. Compose 的 `ToolCard` 标题同样走 `toolNameCn`（原来直接把英文摊在标题上）。
