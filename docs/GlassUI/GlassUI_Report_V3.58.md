## 1. 根因（两层，第一层已修并真机验证）

### 层 1（主因，**已修 + 真机验证过**）
`GlassChatView` 的镜像路径有两次写 Compose 状态：

```java
state.setItems(new ArrayList<>(items));   // ① 立刻：原始列表（对）
pullVisibleLater();                        // ② 120ms 后：用 legacy.visibleItems() **无条件覆盖**
```

② 无条件覆盖：旧视图过滤引擎（`applyFilter`，60ms 延时）**未就绪时返回空表** ⇒ `state.items = []`；
初始加载后不再有 `setItems` ⇒ **永久空**，且这条路径**不报错**（所以既无横幅也不崩）。
V3.50 的节流改动**改了②的触发时机** ⇒ 每次打开会话都踩这个空表。

**真机对照证据**：
| 构建 | 视图 | `uiautomator dump` |
|---|---|---|
| V3.53 | Compose | 6 条文字（只有顶栏/chips/输入框）⇒ **0 消息** |
| 诊断版 | **切回旧视图**（`USE_GLASS_CHAT=false`） | **消息全在**：`全都是空的`/`全空`/`执行了命令 · pwsh`/`已读取文件，修改了文件，执行了命令` |
| 修复版 | Compose | **消息回来**：`手机插上了`/`手机回来了。装修复版并用 UI dump…`/`执行了命令 · pwsh`/`▸ 思考过程 4664 字`/`修改了文件并执行了命令` ✓ |

**修复**（`GlassChatView.pullVisibleNow`）：
```java
List<ChatItem> v = legacy.visibleItems();
// 过滤结果为空、而原始列表非空 ⇒ 丢弃这次空结果（保留原始列表）
if (v.isEmpty() && !lastRawMirror.isEmpty()) return;
```
（过滤结果非空时照旧覆盖 ⇒ 简洁模式过滤行为不变。）
