## 1. 抽屉两处菜单：**换成"项目/模型"同一个组件** ✅

原来抽屉是**自己画的** `SheetLikeOverlay`（半透明卡 + 自绘阴影 + 自绘遮罩），
与对话页的 `GlassSheetOverlay`（模型/项目/权限/用量面板）**是两套代码** ⇒ 材质/圆角/行样式/交互逐版漂移。

**现在**：抽屉把"要开哪个菜单"翻译成**同一个 `GlassSheetState`**，交给**同一个 `GlassSheetOverlay`** 渲染
（30dp 圆角、同款行样式与拖拽条、10dp 磨砂、同款垫底 38%/36%、同款遮罩与返回键）——
**以后改面板只改一处，抽屉自动跟随**。

**证据**：`evidence/v3530/1100_drawer_sheet_same_component.png`（可见拖拽条 + 同款行 + 同款垫底）。
旧函数 `SheetLikeOverlay` 已标注"不再被调用"。

## 2. 桌面补丁的**分发**问题（查实，含实测证据）

### 2.1 这条补丁是什么
DSH 本体的 **v2→v3 会话迁移白名单** `SOURCE_KINDS` 缺 `instruction-hint` ⇒
**含该 source kind 的 v2 会话整条拒绝迁移**（手机端就表现为「这个会话暂时读不到内容…」并反复重试）。

### 2.2 实测（本轮新增工具 `tools/zstd-frames.mjs` + `tools/scan-all-sessions.mjs`）
- ⚠️ 会话文件是**「头帧 + 逐个事件帧」串联多帧 zstd**；Node 的 `zstdDecompressSync`/流式 API
  **都只吃第一帧**（实测 182 个文件只解出 45KB）⇒ 必须**自切帧**（按 zstd 帧结构解析），否则得到"0 命中"的**假阴性**。
- 切帧后：**182 个文件 / 64,516,204 字节 / 4195 帧**；
- 含 `instruction-hint` 的：**19 个**，其中 **18 个是 `session.v2.jsonl.zstd`（= 真正读不出来的那批）**，
  另 1 个是已迁移的 `session.v4`（无害）。
- 写入方排查：`instruction-hint` 在 **DSH 本体 app.asar（0 命中）/ 手机接入插件 pc-plugin（0）/ App 源码（0）** 里都不存在
  ⇒ 是**别的组件或更早版本**写进会话的，**与"手机接入插件"无关**。

### 2.3 结论：**能不能合并进移动设备插件？——不能（作为运行时补丁）**
两条都实测排除了：
1. 白名单是 **bundle 内模块私有的 `const Set`（未导出）** ⇒ 插件拿不到引用，无法运行时改；
2. 那两个文件**不在** `app.asar.unpacked`（`Test-Path` = False）⇒ 插件也无法从磁盘改。
⇒ 只要还是"改 DSH 本体"，别的用户就必须各自手动跑 `.bat`（= 用户不接受的那种方式）。

### 2.4 能"更新插件即自动生效"的路子（推荐 B）
| 方案 | 做法 | 能自动分发？ | 风险 |
|---|---|---|---|
| A 上游修 | 把 `instruction-hint` 加进白名单（= asar 补丁做的事） | ❌ 要等 DSH 官方发版 | 无（但不可控） |
| **B 数据侧归一化** | 插件启动时扫 v2 会话，把越界的 `source.kind` 归一成**既有合法种类**（备份 + 往返校验 + 幂等） | ✅ **用户更新插件即自动跑** | **要回写会话文件**（多帧 zstd），必须严格保持帧布局 |
| C 现状 | asar 补丁 + 手动 .bat | ❌ | 只我这台机器有效 |

⇒ B 是唯一满足"别人不用手动、更新插件就生效"的形态。**读**这一半本轮已经打通并实测（`zstd-frames.mjs`）；
**写**这一半（逐帧 `zstdCompressSync` + 往返校验）与插件接线**尚未做**，且**回写用户会话属破坏性操作** ⇒ 需你一句话确认再动。
