## 1. 批注①：↓ 圆钮

### 1.1 质感"和下面的统一"
下方那批件（顶栏 ‹ / ⋯、底部 ＋ / ↑、输入框胶囊）**全都是真玻璃**：`RefractionWindow`，不带 `tint` 参数时
用的就是 `RefractionWindowTokens.Tint`（**浅色 `White 20%` / 暗色 `#14121C 30%`**）。
上一版的 ↓ 钮是"手绘观感"：4 段白色纵向渐变（顶 0.64）+ 底部品牌淡染 + 内高光弧 + 底部内阴影 ——
和旁边那批**均匀半透明白**放一起就不是一个材质。现在：

```diff
- .background(Brush.verticalGradient(listOf(
-     Color.White.copy(alpha = 0.64f), Color.White.copy(alpha = 0.34f),
-     Color.White.copy(alpha = 0.16f), Color(0xFFEDEBFF).copy(alpha = 0.26f))))
- .border(0.6.dp, Color.White.copy(alpha = 0.62f), CircleShape)
- .drawBehind { 顶部高光弧 + 底部内阴影 }
+ .background(RefractionWindowTokens.Tint)          // 与 ‹/⋯/＋/↑/输入框**同一个值**
+ .border(0.5.dp, Color.White.copy(alpha = 0.45f), CircleShape)
+ .drawBehind { 只留一条 alpha 0.22 的顶部受光弧 }
```

> ⚠️ **为什么不能把它做成真玻璃件**：这一屏已经有 **9 个 `RefractionWindow`**；再加第 10 个（就是它）
> 在真机上**必崩**（V3.40 两次 `RenderThread computeTransformImpl` 递归爆栈，`V3.32 §0` 铁律）。
> 所以只能"体色对齐 + 无模糊"。
> **若你要的是"真玻璃"**：可行路径是**先减掉一个**现有玻璃节点（例如顶栏 ⋯ 改观感版）再加它，
> 让节点数不增加 —— 但这**必须真机冷启动验证**，得你点头再做。

### 1.2 位置"再往下点"
```diff
- bottom = bottomInsetDp + (if (state.subagentCount > 0) 204.dp else 146.dp)
+ bottom = bottomInsetDp + (if (state.subagentCount > 0) 168.dp else 116.dp)
```
实测：↓ 图标中心 **y 1740 → 1835**（下移 **95px = 36.2dp**，与 204−168=36dp 一致）✓
证据：`v3340/111_drag_down_bubble_1.png`（旧）vs `v3420/200_rail_no_pill.png`（新），脚本 `find_down_icon.py`。

## 2. 批注②：刻度尺

### 2.1 去掉"后面的白色底"，只留横条
删掉三样（都是上一轮照参照 `MessageScrubber` 搬来的）：
**30dp 半透明灰底**（浅 `0xEBF7F6FB` 92%）、**灰底发丝描边**、**中间格波轮定位槽**。
它们在参照里的用途是"压住背后的聊天内容"，但落到这屏就是**一整块白板漂在消息上**。

| 检查 | 旧 | 新 |
|---|---|---|
| 灰底区域（x 962..1039, y 960..1345）近白像素占比 | **74.0%**（21938/29645） | **1.3%**（377/29645） |
| 横条位置 | y 1096 / 1130 / 1164 | **y 1096 / 1130 / 1164（一模一样）** |
| 横条高度 | 2.7 / 2.7 / 3.4 dp | 同上 |

⇒ 白底去掉了，横条**位置与尺寸一点没动**（脚本 `measure_bars2.py`；放大图 `201_right_strip.png`）。

### 2.2 横条质感
没有白底可依之后，横条必须自己"立"起来：
- 未选中：主题自适应（浅色深条 / 深色白条）+ **上亮下暗的极小渐变**；
- 当前回合：**品牌双色渐变**（`Ui.BRAND_G1 → BRAND_G2`）+ 加长（22dp vs 13dp）、加厚（3.6dp vs 2.6dp）。

### 2.3 滑动手感：拖动中"每换一格就滚一次"
上一版（V3.34）按参照做成"**抬手才跳一次**"，代价是**拖动过程里列表完全不动**、只有横条和气泡在变。
本轮改成：`onDrag` 里**只在换到另一格的那一刻**滚一次（不是每个 MOVE 都滚，因此不会和手指打架），
抬手时 `onDragEnd` 再精确落一次。外加换格触感反馈（`TextHandleMove`）。

| 检查（拖动中相邻帧、干净区域互相关） | 旧 | 新 |
|---|---|---|
| 拖动中列表竖向位移 | **0 px**（全程不动） | **−229 px（−87dp）** ⇒ 跟着走 |

证据：`v3420/220_at_top.png` → `221_livedrag_0..5.png`，脚本 `check_live_scroll.py`。

> ⚠️ 判据踩坑留档：第一次用互相关测"有没有滚"，区域取了 y 600..1700，结果恒为 0 —— 因为
> **浮动的目标卡（`zIndex`）不随滚动移动**、**预览气泡固定在中轴**，两者都在那个区域里，把互相关带偏了。
> 换到 y 1450..2120（下方干净区）才测出来。

## 4. 仍开放的判断（需要你的口味）

1. **横条够不够显眼**：没有白底之后，横条直接压在聊天气泡上。当前用"主题自适应色 + 极小渐变"顶着；
   如果你觉得还是"看不清"，可选：加一层**很淡的投影**（只给当前那条）、或把未选中条再压暗一档 —— 都是单参数改动。
2. **拖动中"跳一下" vs "平滑跟"**：现在是每换一格 `scrollToItem`（瞬时跳）。要更顺滑就得做**按比例滚动**
   （不再是固定 10 格窗口），那是结构改动，建议先看真机手感再定。
3. **↓ 钮要不要真玻璃**：见 §1.1 的路径（减一个再加一个），需要真机验证。
