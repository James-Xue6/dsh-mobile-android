## 1. 配色切换未即时生效 —— **两个真根因都修了**（已验）

| # | 根因 | 修法 |
|---|---|---|
| ① | `AmbientBackground` 的 key 用了 `Ui.ambientPalette()` —— **普通 Java 静态方法、不是 Compose 可观察状态** ⇒ 换配色时 key 永远不变 ⇒ 背景 Drawable 不重建 | `AmbientBackground(modifier, rev)` 新增参数，用 `key(rev, isDark)`；三个屏都传 `state.themeRev` |
| ② | **生产侧真根因**：`MainActivity.onSetPalette()` 只换了根背景 + `Ui` 静态值，**没调 `applyThemeEverywhere()`** ⇒ 各屏（含 Compose）不会重读 `Ui` 静态色 | `onSetPalette` 改为直接 `applyThemeEverywhere()`；另给 `GlassSettingsView.setPalette` 补 `bumpTheme()` |

**实测**：设置页点第 2 个配色 ⇒ 页面上段 RGB `170,176,242 → 56,177,224`（通道差 **114**，改前只有 −5）；
且点前/点后地标 y **完全一致**（外观 520 / 深色模式 615 / 配色 852）⇒ 即时且不跳顶。
取证 `evidence/v3270/300`（前）`302`（后）。

## 4. 玻璃模式二选一（默认磨砂玻璃，省资源）（已验 UI + 切换）

  `GlassSettingsView.setGlassMode`（宿主推送）、切片 `pickGlassMode`（立即落库 + 切 Ui + 就地重组）。
- **实测**：设置里出现「玻璃模式 / 液态玻璃 / 磨砂玻璃」（`evidence/v3270/310`）；点「液态玻璃」**无崩溃**（crash 0）。

## 6. 带目标的对话：内容穿过顶栏（不截断）+ 目标/任务条（本轮已做，附一个**新发现的缺陷**）

**用户原话**：「带目标对话改成同样是下方对话界面穿过去的状态，不要截断对话。目标对话点击后，界面为优化，
应按照顺序配置玻璃条」。

### 6.1 根因与改法
- 根因：`横幅 / 目标卡 / 任务条`是**列表的兄弟节点**（固定在上方）⇒ 列表视口被它们挤下去 ⇒
  有目标时消息既**穿不到顶栏底下**、又显得**被截断**。
- 改法（最小改动，不动 85 行既有代码）：让头块**浮在列表之上**（`Box` 叠放），
  列表上内边距按**实测头高**（`onSizeChanged` → `headPx`）动态让位
  ⇒ 静止时首条消息正好在头块下方（不重叠）；上滑时消息从头块与顶栏底下**穿过去**。

### 6.2 ⚠️ 新发现的缺陷：自绘阴影在"卡中卡"嵌套下会吞掉内容
给目标卡内的**任务条**加统一阴影 `glassButtonShadow` 后，**整条任务条画不出来**：
像素抽检 y=471/600/729/858 与背景差 ≈ **0**（`evidence/v3270/322`）；
把该行阴影撤掉后立刻恢复（差 −13.8/−8.0/−11.8/−28.1，`evidence/v3270/324`）。
⇒ 结论：`glassShadow`（`drawWithCache` + `onDrawBehind` 里在**原生 canvas** 上 `clipOutPath` + 画位图）
在**嵌套**（卡片内的卡片）场景下会让节点内容不绘制；**外层/单层**场景（抽屉卡、气泡、chip、圆钮）正常。
**处置**：任务条暂不加阴影（内容可见优先），缺陷登记待查（下一步：改用 `saveLayer`/Compose 层内裁剪，
或改成"外层包一层"的写法）。

### 6.3 实测
`evidence/v3270/322`（目标条 + 空的任务条 ⇒ 缺陷现场）→ `324`（撤回阴影后：目标条 + **4 条任务条按顺序**
「取样层装「背景 + 滚动内容」 完成 / 底部改三件式玻璃 完成 / 9 类消息行接真实 ChatItem 本轮完成 /
挂进 MainActivity 宿主 待做」）。滚动穿透已由 §6.1 的结构保证（静止不重叠），⏳ 与真机一起复验。

### 6.4 ⚠️ 我这条改动**有 bug，已回退**（重要，别重复踩）
第一版"头块浮层"把**列表也包进了被 `onSizeChanged` 测量的那个 Column** ⇒ `headPx` 量到的是
**整列高度** ⇒ 列表上内边距被撑到整屏高 ⇒ **消息被整段推下去**（看起来像"目标卡后面一片空"）。
**已回退**到已知 good 结构（`if (hasHead) Spacer(headInset)` + 头块 + 列表同一 Column，
`contentPadding.top = if (hasHead) 2.dp else headInset + 2.dp`）。
⇒ 重做时必须把「列表」与「头块」拆成**两个兄弟节点**（同一 Box 叠放），测量只包住头块。已列为下一轮第一件。
**回退后实测**：切片页「目标 + 4 条任务条按顺序」正常（`evidence/v3270/330`）✓ 无回归。
