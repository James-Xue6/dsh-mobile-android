## 2. 路线 A 的三条硬规则（违反就出问题，全部有实测证据）

1. **取样层 = 背景 + 可滚动内容**；玻璃件一律留在**层外**（层内放真玻璃会自取样 ⇒ 卡片里看不到背景）。
2. **层内内容用半透明卡**（浅色白 26% / 深色 `#14121C` 30% + 发丝边）。
3. **浮层（弹窗/抽屉）取样的两种合法方式**：
   - 渲染在**各自屏的同一棵 Compose 树**里、且在层外（`GlassSheetOverlay` 就是这套）；
   - 或沿用旧引擎（`Ui.blurredGlassRoot`，能抓窗口背后）——**抽屉外壳**目前就是旧引擎玻璃。

## 7. 事故与教训（**必须避免重犯**）

1. **未验证就批量改视觉** ⇒ 用户明确反馈"你又开始瞎改了，刚才改动的都出问题了"。
   **规矩**：一次只改一处；改完先编译、再在真机/模拟器看到结果；审美类改动**先看现状截图**再动。
2. **PowerShell 嵌套数组陷阱**：`@( @('a','b'), @('c','d') )` 在 `foreach` 里被展平 ⇒ `$p[0]` 取到**首字符**
   ⇒ 对整文件做逐字符替换（`s→i`、`.→p`、`C→o`），把 `GlassSheet.kt` 彻底改坏（218 行全是 `impori/oodifier`）。
   **规矩**：批量改写用逐条 `Replace` 或 `edit` 工具，禁用嵌套数组+索引；改完必须立刻编译。
   （本轮已按 V3.18 内容整文件复原；其余被脚本碰过的文件复查完好。）
3. **`Add-Content` 追加被随后的 `Set-Content` 覆盖**：先 `Get-Content -Raw` 再追加、最后写回旧内容 ⇒ 追加丢失。
   **规矩**：追加放在所有重写之后。
4. **多行结构替换过度匹配**多留一个 `}` ⇒ 语法错。**规矩**：替换后立刻编译。
5. **同名方法合并成回环**：动作接口的 `setXxx` 与包装类"宿主推状态"的同名方法撞名 ⇒ 推状态又触发落库。
   **规矩**：动作侧命名 `pickXxx`，状态侧 `setXxx`。
6. **小尺寸元件不要直接套玻璃节点**：`RefractionWindow` 内部是 `BoxWithConstraints`，只给高度约束会**撑满父宽**
   （三个 chip 变成三条通栏叠住）；小元件沿用默认折射（14dp/28dp）会把标签推挤得"位置变形"。
7. **主题切换要 `key(state.themeRev)` 包住整屏**：否则 `GlassAppTheme`（Material3 配色桥）与
   `AmbientBackground` 的 `key(...)` 在**外层作用域**不重建 ⇒ "只有字体变色、背景不变"。
8. **View 背景按 padding 盒绘制**：把玻璃底挂在会带 padding 的容器上 ⇒ 被裁短/形状错位（抽屉那条"边"）。
   修法：玻璃底放**不带 padding 的独立子 View**（`DrawerHost.bg`），且 `onMeasure` 里与抽屉同宽，
   `applyTx` 一起平移；**`applyDrawerBg()` 必须在 bg 建好之后调用**（顺序写错会 NPE 闪退）。
9. **`ConversationView` / `SettingsView` / `SessionListView` 都是 final 类** ⇒ 用**同名双写包装**（组合，不继承），
   MainActivity 的调用点几乎零改动。
10. **抽屉里 Compose 取样不到页面**：抽屉外壳是旧引擎玻璃（Java drawable），Compose 录不到
    ⇒ 抽屉内的按钮/卡片**不能用真玻璃**（用"玻璃观感"：斜向白渐变 + 0.5dp 发丝边 + 顶高光）。

- **真机**：`A7QK023224004563`（HONOR PGT-AN10，1312x2848 @560dpi，fontScale 0.85）
  - **安装会弹系统确认框**（`PackageInstallerActivity`）。已验证的可行序列：
    `am force-stop com.android.packageinstaller` → `adb install -r app\build\outputs\apk\release\app-release.apk`；
    若仍弹框**只能人工点「继续」**（用户可打开类似「通过 USB 安装应用」的开关永久免确认）。
    ⚠️ `settings put secure adb_install_need_confirm 0` 在本机被拒（`--user not supported for delete and put`）。
