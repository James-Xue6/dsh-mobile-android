# GlassUI 迭代报告 V3.90 | 2026-10-11（生成物窗口"关不掉"：根治 —— 回帧不再重开面板）

> **触发**：用户「你看现在的截图，**生成物这个窗口还是无法关闭**」（附截图未随消息送达）。

---

## 1. 先排除：关闭路径本身是通的

查了三处关闭入口，都正确接到 `GlassSheetState#hide()`（`visible = false`）：

| 入口 | 位置 |
|---|---|
| 遮罩点击 | `GlassSheet.kt:309` `.glassTap { onDismiss() }` |
| 系统返回键 | `GlassSheet.kt:354` `BackHandler { onDismiss() }` |
| 底部「关闭 / 取消」按钮 | `GlassSheet.kt:483` `.glassTap { onDismiss() }` |
| 聊天页接线 | `GlassChatScreen.kt:870` `onDismiss = { state.sheet.hide() }` |

⇒ 既然"点了没反应"，那只有一种解释：**它被再次打开了** ✓

## 2. 根因：**我 V3.87 自己写的那行"回帧后重画"** ✗

V3.87 为了把 `file-list` 的异步结果补进面板，我在 `onFileList` 里回调了 `onArtifacts()`：

```java
if (... < 2500L) runOnUiThread(this::onArtifacts);   // ← 每次回帧都**重新打开**面板
```

⇒ 你**刚点关闭**、回帧刚好到达 ⇒ 面板又弹回来，看着就是"关不掉" ✗。
（V3.89 我把窗口从 15 秒缩到 2.5 秒 —— 那只是让它**更难撞上**，**没有根治** ✗。这是我的判断失误。）

## 3. 根治

| 改动 | 说明 |
|---|---|
| `onFileList` **绝不碰 UI** | 只更新 `workspaceFiles` 数据，**不再有任何**重新打开面板的动作 ⇒ 关掉就是关掉 ✓ |
| **换会话时预热** | `subscribe()` 之后顺手 `requestFileList(...)` ⇒ 你点开面板时清单**已经在了** ⇒ 不需要那种危险写法 ✓ |
| 点「生成物」时仍会发一次请求 | 数据随后刷新，**下次打开**即最新（面板本身不再被打扰）✓ |
