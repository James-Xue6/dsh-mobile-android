## 0. ⚠️ 先报一条**方法学结论**：模拟器测量台不能用来归因

⇒ **本报告不拿这些数字做结论**。要做卡顿验收，只有两条路：

## 3. ③抽屉菜单：**照抄"模型/项目面板"那套材质**

## 4. ④滑动降档：已实现（你给的建议）

- `RefractionWindowTokens.quality`（默认 `1f` = **与此前完全一致**）：只缩放**模糊半径**与**折射幅度**，
  并在降档时**关掉色散**（另一笔重开销）。
- `GlassChatScreen` 里按"首可见项序号变化 / 时间"当速度：`≥1.5 → 0.35`、`≥0.6 → 0.65`、否则 `1f`；
  **停手立刻回满档**。玻璃件本体的绘制逻辑一行没动。
- ⚠️ 注意：这条**目前没法验证收益**（§0 的原因），也无法断言它在真机上一定有感 —— 需要真机滚一次看 P99。

### 关于「性能损耗大吗 / 能不能用 GPU」的答复（**含未核实项**）
- 本工程有**两条**模糊路：① `Ui.BackdropBlurDrawable`（**明确的 CPU 自绘**：降采样 1/4 + 盒式模糊，60ms 一帧刷新）—— 旧引擎用的；
  ② Compose 的 `RefractionWindow`（`drawBackdrop { blur/vibrancy/lens }`）—— 新玻璃件用的。
- ②按 API 形态是**在 RenderThread 上跑 Skia 着色器**的路径（`lens` 那种形变+色散不是 CPU 箱式模糊能做出来的）
  —— ⚠️ **这一条我本会话没有解包 AAR 逐行核实**，要确认我可以去解。
- 无论哪条，**每帧真正贵的是"离屏层捕获"**（每个玻璃件背后那块内容要被渲染进一张纹理；层数 × 面积决定开销），
  这也正是你转述的"内置效果分级与 shader 缓存 / 复杂效果走离屏合成"那句话的由来。
- 你说的"**按设备能力动态减少 lens 层数**"= 下一步可做（设备分级：低端机默认 0.6 档）；本轮先做了"**按速度降档**"。

## 5. ⑤目标胶囊：因「还是很透」改成**同体色的观感版**（并撤掉额外那一层）

- V3.46 把它做成真玻璃时，为了不让它自取样，**额外加了一整层 `contentBackdrop`**（一次全屏离屏捕获）。
- 本轮按你的"**还是很透**"改成：**子智能体条同值体色**（浅白 32% / 深 `#14121C` 22%）+ 19dp 圆角
  + `heightIn(min = 38.dp)`（收起与子智能体条**同高**），**纯绘制、不加玻璃件、不加层**。
- ⚠️ 说明：这**不是"真玻璃件"**（真玻璃需要新增节点，撞同屏 ~10 个的上限）。要真玻璃版，代码注释里留着回退路径。
