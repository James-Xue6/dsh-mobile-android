# GlassUI 迭代报告 V3.91 | 2026-10-11（顶栏渐变遮罩：改成**从上传图片取色**）

> **触发**：用户「发现个 bug：对话框上方的渐变遮罩，我切换成上传的图片之后，上面显示的**别的颜色**的遮罩，
> 能不能**从上传图片提取**？」

---

## 1. 根因

聊天页顶栏那层渐变遮罩，5 个色标**全部取自 `Ui.ambientBarColor()`** ——
而它是**内置 6 套配色**推导出来的颜色 ✗（`GlassChatScreen.kt:699-705`）。

⇒ 一旦把环境底换成**用户上传的图片**，顶栏那层还在用"配色的顶色"⇒ 与图片颜色对不上，
看起来就是"上面盖了一层别的颜色" ✓。

## 2. 修：解码上传图时**提取顶部代表色**，顶栏优先用它 ✅

| 位置 | 改动 |
|---|---|
| `GlassAmbientImage` | 新增可观察状态 `topColor: Int`（ARGB；`0` = 没有/还没提取到） |
| `AmbientBackground` | 解码上传图后**顺手算**顶部代表色并写回 `topColor`（在 IO 里算，不占主线程） |
| 新增 `topAverageColor(bmp)` | 取图片**顶部约 12% 区域**的平均色（忽略透明像素）；**稀疏采样**（每行隔若干列、最多 48 行）⇒ 几千像素量级，不会卡 |
| 新增 `ambientTopColor()` | **有自定义底图 ⇒ 用图片顶部色**；没有 ⇒ 回落到 `Ui.ambientBarColor()` |
| 聊天页顶栏渐变 | 5 个色标改用 `ambientTopColor()`（含 `alpha = 0` 的收尾那一段） |

因为 `topColor` 是 Compose 可观察状态 ⇒ 图片解码完成的那一帧**自动刷新**顶栏（无需重启/重建）；
第一帧可能还是配色色（图还没解完），随后立刻纠正 ✓。

**约定**：以后页面里凡是要"与顶部环境同色"的地方，都该用 `ambientTopColor()`，不要再直接读 `Ui.ambientBarColor()`。
