# 弹窗制作规范（Dialog SPEC）· dsh-mobile-android

> **强制**。用户 2026-10-11 明确要求：「**配置个制作规范，弹窗必须统一成玻璃弹窗风格**」。
> 背景：`待发送 → 修改` 点开后又弹出一个**系统 AlertDialog**（白底、方角、与液态玻璃语言完全不符），
> 同一个 App 里两种弹窗语言并存 —— 这类"漏网的老弹窗"必须系统性清掉。

本文与 `GlassUI_SPEC.md`（玻璃质感规范）配套：**质感参数看那份，弹窗形态看这份。**

---

## 1. 唯一允许的弹窗实现

**所有**弹窗一律走玻璃骨架：`glass/GlassSheetOverlay` + `glass/GlassSheetState`。

- 入口：`GlassChatView#showSheetList / showSheetForm`（Java 侧）；
  Compose 侧直接操作 `state.sheet`（`showMenu / showList / showConfirm / showForm`）。
- **禁止新增**：
  - `android.app.AlertDialog` / `Ui.dialog(...)`（系统对话框）
  - `ui/ModelSheet.showOptions/showText/showInput(...)`（旧弹窗体系）
  - 任何自绘的"圆角白底卡片 + 两个按钮"

> 旧代码**保留**可用的回退分支（非玻璃宿主时），但**新功能一律玻璃**，且回退分支要在代码里写明"回退落点"。

## 2. 四种形态（按语义选，不要自创第五种）

| 语义 | 用什么 | 关键点 |
|---|---|---|
| 列几个动作（重命名/归档/下载…） | `showList` | 收口按钮文案用 `listCloseLabel`；**空态也要走 list**（"列表形态但 0 项"能表达空态）|
| 危险操作要二次确认 | `showConfirm` | `danger = true` 时主按钮转红 |
| 要用户填内容（改排队内容、手动加设备…） | **`showForm`** | 字段用 `GlassSheetField(label, value, hint, password)`；`onSubmit` 返回 `null`/`""` = 成功收起，返回文案 = **内联报错且保持打开**（不要用 Toast 报错）|
| 菜单项（带图标 + 说明） | `showMenu` | 与列表形态互斥 |

## 3. 宿主位置（**最容易写错的一条**）

**规则（用户 2026-10-12 定调）：每个界面各自有一个玻璃弹窗宿主，弹窗挂在"该界面自己那一层"的最上层。**

| 界面 | 它自己那套（状态 + 渲染宿主）| 取样层 |
|---|---|---|
| 设备页 / 首页 | `GlassDeviceState.sheet` + `GlassDeviceScreen` 根 Box 末尾的 `GlassSheetOverlay` | 本页 `backdrop` |
| 设置页 | `GlassSettingsState.sheet` + `GlassSettingsScreen` 根 Box 末尾的 `GlassSheetOverlay` | 本页 `pageBackdrop` |
| 对话页 | `GlassChatState.sheet` + `GlassChatScreen` 里的 `GlassSheetOverlay` | 对话页 `backdrop` |
| 侧抽屉 | `MainActivity.drawerSheetState` + `DrawerHost` 里那个独立全屏宿主 | `GlassDrawerBackdrop` |

**改弹窗一律走路由**：`MainActivity.currentSheetState()`（抽屉开着 ⇒ 抽屉；设置页 ⇒ 设置页；对话页 ⇒ 对话页；
其余 ⇒ 设备页），或直接用它的三个包装：`glassInScreenList / glassInScreenForm / glassInScreenConfirm`。

- ❌ **禁止**把某个界面的弹窗写到**对话页**的状态上（例如 `((GlassChatView) convo).showSheetForm(...)`）——
  用户停在设备页/设置页时**对话页根本没被组合** ⇒ 弹窗**没人渲染**：真机就表现为"**透明的**"或"**跑到对话窗口去了**"。
  （这条已踩两次。用户原话：「**每个界面的玻璃弹窗都应该在对应界面的位置最上层**……为什么都给我搞到了对话窗口」。）
- ❌ **禁止**挂在**窄容器**里：抽屉面板（`DrawerHost` 那块 ~360dp）、任何 `Box` 局部区域。
  挂在窄容器里的后果真机实测两条：① 面板内居中 ⇒ 看起来偏在左侧；
  ② 有人用 `padding(start = 2×shift)` 硬挪 ⇒ **padding 超过容器宽** ⇒ 弹窗退化变形。
- ✅ 抽屉/窄面板里的 ⋯ 菜单、会话操作等，**一律回调宿主**，由**抽屉自己那个**全屏宿主渲染（不是对话页那个）。
- ✅ 只有"当前界面确实没有玻璃宿主"时才回退旧实心弹窗；**不允许**写进一个没人渲染的状态。

### 3.1 ❌ 反面案例（2026-10-12，真机取证定案）

**症状**：「修改名称」「粘贴配对串」等弹窗**第一次**打开是**旧弹窗**，进对话再回来才变玻璃。

**错误写法**：

```java
if (convo != null) {                        // ✗ 用"视图存在"当玻璃门
    glassInScreenForm("renamedev", ...);
}
... 旧弹窗 ...                               // convo==null ⇒ 落这里
```

`convo`（`GlassChatView`）是**懒建**的 ⇒ 设备页/设置页上为 **null** ⇒ 玻璃尝试被跳过 ⇒ 旧弹窗 ✗。
**正确**：直接调 `glassInScreenForm / glassInScreenList / glassInScreenConfirm`（路由不需要 `convo`）。

**排错纪律**：同一现象反复出现且**连续两轮猜测未命中** ⇒ **先建运行时取证**（本机 `adb logcat` 抓不到应用日志，
改用 `getExternalFilesDir(null)/sheet-diag.log` 落文件 + `adb shell cat` 拉回），**再改代码**。

## 4. 材质（与 GlassUI_SPEC 一致）

- 面版：`RefractionWindow(radius, tint, blurRadius)`；**体色必须显式给**（浅色白 ≈58% / 深色 `#14121C` ≈66%），
  否则背后文字会读得出来（真机截图实证过）。
- 磨砂 `blurRadius = 10.dp`（面板是大面积件）。
- 尺寸统一由 `SheetK` 缩放；行高/字号规则见文件内注释，**不要**在调用处另起一套。
- 一次迭代 ≤2 个质感数值（SOP）。

> ⚠️ **上一条的"体色必须显式给"已于 V3.98 作废**（这是血的教训，保留在此以示警）：
> V3.96 我按它给 `GlassSheet.kt` 加了 `tint = 白 58%`，**本意只修抽屉里那一张**，
> 但这个组件是**所有弹窗共用**的 ⇒ 权限 / 模型 / 生成物 / 任务…**全部变成白底**，
> 用户当场发现并质问「你怎么改我界面了？」✗✗
>
> **新规则（强制）**：
> 1. **共用组件不许为单一场景改材质** —— 要分场景，就加**可选参数**，且**默认值必须逐字等于原行为**；
> 2. 改任何跨页面复用的玻璃件前，先 `grep` 它的调用点，**列出受影响的页面**并写进报告；
> 3. 默认**保持玻璃**（`RefractionWindow` 不给 `tint`，走引擎默认体色）——"太透"这类观感问题，
>    优先在**该场景的容器层**解决（如抽屉底色），不要动共用面版。
