4. ⭐⭐ **"目标看不到"定论（V3.29 第 6 轮，日志页现场证据）**：
   我在 `MainActivity.applyGoal()` 里加了目标帧留痕（keys/length/前 24 码元的十六进制）→ 经 `[事件流]`
   进日志页。**实测**（生产设置页 → 日志页，共 **98 行**，滚到底取 `evidence/v3270/420~423`）：
   - 事件流尾部是：`evt step/start` / `evt assistant/message` / `evt tool/call` /
     **`tasks 帧 sid=1e1c526b n=null`（两次）**；
   - **整份日志里没有任何「目标帧」记录** ⇒ **`applyGoal()` 从未被调用** ⇒
     **网关压根没给这个会话推过 goal 帧**。
   - 同时 `tasks 帧 … n=null` 说明**任务帧里没有 todos** ⇒ 这也解释了「任务 0/0」。
   ⇒ **结论：不是 App 渲染问题，是网关侧没把 goal/tasks 内容推给手机**（App 侧已经把"收到没收到"留痕，下次一打开日志页即可对质）。
   - 附带：卡片此前"渲染成空目标"是因为我第 4 轮把渲染条件放宽到 `planProgress 非空`（那时进度 `0/0` 已到）——
     即"有进度、无目标"。现已能自证清白。
   - 给卡片加了**自诊断**：`planGoal` 空白时改为渲染 WARN 色文案「（目标文本未到达：objective 为空）」；
     同时把渲染条件放宽为 `isNotBlank() || planTodos 非空 || planProgress 非空`。
   - 真机/模拟器实测（生产对话页）：目标行上**只有**「目标」(x=79) 与「0/0」(x=952)，
     **中间既没有正文节点、也没有我那条诊断文案** ⇒ 说明 `state.planGoal` **既不是空白也不是可显示内容**
     （典型是**零宽字符/控制符**：`String.isBlank()` 对 U+200B 之类返回 false，于是诊断分支不触发，
     而 Text 又画不出任何字形）。
   - 结论：**卡片没坏，坏的是"网关送来的 objective"**；todo 进度同样为 `0/0`。
   - **下一步（唯一能定论的）**：把目标帧的**原始 JSON 键/长度**写进 `evtLog` → 日志页，
     现场打开日志页即可看到"网关到底发了什么"（`MainActivity` 的 `applyGoal` 那一帧）。
   但渲染成 **「目标」+ 空文本 + 「0/0」** ⇒ `state.planGoal` 是空/空白、进度 `0/0`
   ⇒ 不是"卡片没渲染"，是**目标内容没到**（数据/映射侧）。下轮查
   `MainActivity` 的 `planGoal = cur.optString("objective")` 那帧是否真带 `objective`、
