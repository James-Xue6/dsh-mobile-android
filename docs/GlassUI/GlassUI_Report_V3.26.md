## 2. #2 玻璃按钮阴影**模板**（已完成模板 + 已铺开，模拟器已验）

### 2.1 口径来源（关键发现）
Java 侧**早就有唯一出处** `Ui.shadowed(...)`，而且**投影色是紫调的** `Ui.GLASS_SHADOW = 0x3D1A1042`
（rgba(26,16,66)≈24%，**不是黑**）；两级内缩 `Ui.BTN_SHADOW_PAD = 6dp` / `Ui.CARD_SHADOW_PAD = 18dp`。
⇒ #1 那圈黑边正是因为 Compose 侧那句用了**默认黑**投影（两套实现各写各的）。

### 2.2 模板（`GlassAmbient.kt`，数值只在这**一处**）
```kotlin
object GlassShadow {           // 与 Java 侧 Ui.shadowed 同口径
    val ButtonPad = 6.dp       // = Ui.BTN_SHADOW_PAD
    val CardPad   = 18.dp      // = Ui.CARD_SHADOW_PAD
    val color get() = Color(Ui.GLASS_SHADOW)
}
fun Modifier.glassButtonShadow(shape: Shape)   // 按钮/胶囊
fun Modifier.glassCardShadow(shape: Shape)     // 卡片/大面板
```
用法纪律：**必须排在 `clip/background` 之前**（同 V3.21 按压双影教训：修饰符外侧先画）。

### 2.4 ⭐ 关键实现坑：`Modifier.shadow` **不能用**（会从半透明件里透上来）
第一版直接用 `Modifier.shadow(elevation, ambientColor, spotColor)`（色已换成紫调），按钮看着没问题，
但**卡片下缘出现一道深灰带**（`evidence/v3260/141`/`142` 放大可见）。

根因与 Java 侧注释里记的**一模一样**：`Modifier.shadow` 是"在形状**背后填一层**模糊形状"，
而玻璃件是**半透明**的 ⇒ 那层会透上来压灰卡面（`Ui.java` 原文：「阴影会透上来把卡面压灰
（2026-10-06 逐像素反推：卡面被额外叠了约 24% 的黑）」，所以他们才做 `ShadowedDrawable`）。

**最终实现（照抄 `ShadowedDrawable.draw` 的三步）**：
1. 阴影形状 = 内缩/外扩 `pad`、**整体下移 `pad×0.28`**；
2. **只画在形状之外**（第 i 圈 = 外扩 `w=pad×i/steps` 的边缘上贴宽 `pad/steps×1.6` 的描边
   ⇒ 描边整体落在形状外），alpha 按 `(1-f)²` 二次衰减；
3. **形状顶边以上一律裁掉**（`clipRect(top = 0f)`）—— 否则"元素顶上飘着一圈灰"（Java 第 ③a 步同款）。

**迭代记录（都在模拟器上看过）**：
| 版本 | 参数 | 结果 |
|---|---|---|
| A | `Modifier.shadow(18dp)` | 卡片下缘深灰带（透上来）✗ |
| B | 6 圈描边 | 台阶感，像描了一圈轮廓 ✗（`146`） |
| C | 24 圈 + dy + **顶部裁剪** | 平滑，但浅底上偏灰（`148/149`） |
| D | C + 系数 `0.55→0.30` | 轻微浮起（`156`），但**用户第 2 轮反馈：仍像"双层框"、太硬** |
| E ✅ | **Compose `Modifier.dropShadow` + 方向偏移 + 柔和色** | 真模糊、**只画形状之外**（不透灰）、**右下方向**、更柔（`171`/`172`） |

### 2.4.1 ⭐ 用户第 2 轮修正（本轮定稿口径）
用户原话：「阴影都**便宜**了，而且是**双层框**；阴影最好不要四周一直，**延续玻璃的高光逻辑，左上角打下来，上面阴影少些、下面阴影多些**，但整体要**柔和些不要太强**。」

- **"双层框"根因**：D 版是"沿形状外缘叠描边"⇒ 紧贴形状那一圈 alpha 最高，读起来就是**第二道边框**。
  ⇒ 弃用描边，改用 **`Modifier.dropShadow(shape, Shadow(radius, spread, color, offset))`**：
  **真模糊投影**，且官方实现**把形状内部裁掉**（只画形状外）—— 正好满足"不透上来压灰"这条硬约束。
- **方向**：`offset = DpOffset(pad×0.14, pad×0.52)` ⇒ 光从左上打、影子往**右下**投（上面少 / 下面多）。
  像素抽检：卡片**下方比上方暗 19.5**（`171`；对照带被相邻卡污染，仅作参考）。
- **柔和**：新增 `GlassShadow.softColor`（基色 `Ui.GLASS_SHADOW` 的 **70%**）+ `radius = pad × 0.85`。

> **API 落点备忘（连踩 3 次）**：`dropShadow` 在 `androidx.compose.ui.draw`；
> 它要的 `Shadow` 是 **`androidx.compose.ui.graphics.shadow.Shadow`**（**不是** `graphics.Shadow` —— 那是文字阴影类）；
> 其 `offset` 是 **`DpOffset`**（不是像素 `Offset`）⇒ 模板函数**不需要**密度换算。

**按钮强度**：用户看完 6dp 说「可以调大点」⇒ `GlassShadow.ButtonPad = **10dp**`。
**卡片**：用户说「加上」⇒ 会话列表卡片挂 `glassCardShadow`（`CardPad = 18dp` = `Ui.CARD_SHADOW_PAD`）。
**待用户真机裁定**：柔和度/浓度是**两处旋钮** —— `softColor` 的 0.7 系数、`ButtonPad`/`CardPad`。

### 2.4.2 ⭐ 用户第 3 轮修正（带标注截图，本轮定稿）
用户标注原话：
- **标记点1（抽屉三颗圆钮）**：「这块现在**玻璃质感不强了**，而且怎么感觉**阴影在玻璃圆按钮内部也有影响，阴影应该只在外侧**，整体阴影**过大缩小一半**」
- **标记点2（会话卡）**：「阴影**扩散过大**，而且同刚才那个阴影**在内部也有**」

| 问题 | 根因 | 处置 |
|---|---|---|
| 阴影**在内部也有** | `dropShadow` 是真模糊，但**模糊会把投影铺到形状内部**；玻璃件半透明 ⇒ 透上来压灰 | **离屏合成 + 形状内 Clear**：`graphicsLayer(CompositingStrategy.Offscreen)` → `dropShadow` → `drawWithContent { 用 BlendMode.Clear 把形状内部擦掉; drawContent() }` ⇒ 阴影**只剩形状外** |
| 阴影**过大** | 初版 `ButtonPad 10dp / CardPad 18dp`、半径系数 0.85 | **砍半**：`ButtonPad = 5dp`、`CardPad = 10dp`，半径系数 `0.6`，方向 `(0.10, 0.35)` |
| 圆钮**玻璃质感不强了** | 上一轮把白渐变下端从 10% 提到 **26%** ⇒ **下端太厚、不透** | 渐变定为 **55% → 14%**（上端受光、下端收回去，更陡更像玻璃） |

**取证**：圆钮放大 `evidence/v3260/182`（外侧小阴影、内部干净）→ 三代定稿 `187`；卡片 `183`；整屏 `181`/`186`。

> 硬约束（不夸大）：抽屉外壳是**旧引擎（Java）玻璃**，Compose **取样不到页面** ⇒ 那三颗钮做不了真模糊，
> 「玻璃质感」只能靠 填充白度/发丝边/内层高光 三件套。若还要更像玻璃，剩下的杠杆只有：
> ① 更亮的受光棱 ② 更透的填充 ③ 改抽屉外壳那层（属 Java 侧，动它影响面大）。

### 2.4.3 ⭐ 用户第 4 轮修正（带标注）：**方形切角 / 边缘裁剪** ⇒ 回到平台投影
用户标注原话：
- **标记点1（抽屉刷新圆钮）**：「阴影还是有问题，有**边缘裁剪**而且**投影是方的**」
- **标记点2（会话卡）**：「阴影成**方形切角**了，不是跟随胶囊的形状了」

**根因**：上一版为了"擦掉形状内的阴影"必须用**离屏层**（`CompositingStrategy.Offscreen` + `BlendMode.Clear`），
而**离屏层的尺寸 = 节点尺寸** ⇒ 投影超出节点的那部分**被层裁掉**，圆角矩形的模糊被矩形边缘切断
⇒ 看起来就是"投影是方的 / 方形切角 / 边缘裁剪"。

**四轮试错的最终结论（Compose 里三者不可兼得：跟随形状 / 不被节点裁 / 完全不进内部）**：

| 方案 | 跟随形状 | 不被裁剪 | 不进内部 | 结论 |
|---|---|---|---|---|
| `Modifier.shadow`（大 elevation） | ✓ | ✓ | ✗（透上来压灰） | 用户报"下缘深灰带" |
| 形状外**多圈描边**（仿 Java `ShadowedDrawable`） | ✓ | ✓ | ✓ | 紧贴形状那圈最重 ⇒ 用户报"**双层框**" |
| `Modifier.dropShadow`（真模糊） | ✓ | ✓ | ✗（模糊铺进内部） | 用户报"**内部也有影响**" |
| `dropShadow` + 离屏层 + `Clear` | ✓ | **✗（离屏层裁）** | ✓ | 用户报"**方形切角**" |
| ✅ **平台 `Modifier.shadow` + 小 pad + 低 alpha** | ✓ | ✓ | △（轻微） | **本轮定稿**：`elevation = pad×0.7`、`softColor`(70%)、`clip=false`；spot 阴影天生**左上打光**（方向也对） |

**代价说清楚**：平台投影是在形状**背后填一层**，玻璃半透明 ⇒ **仍会轻微透上来**（比第 1 版 18dp 时轻得多）。
若要**同时**"跟随形状 + 不裁 + 零内部影响"，剩下的唯一路子是**给元素外面再包一层更大的节点**
（层比内容大 ⇒ 不裁），那要改每个调用处的布局，属于结构性改动 —— 已记为备选，等用户点。

**取证**：圆钮 `evidence/v3260/192`、卡片 `193`、整屏 `191`。

### 2.4.4 ⭐ 用户第 5 轮（带标注）「内部有很淡的**8 边形**阴影边缘」⇒ 定稿：**自绘模糊投影 + `clipOutPath`**
用户标注原话：
- **标记点1（抽屉圆钮）**：「按钮内部怎么还有很淡的**8 边形**阴影边缘」
- **标记点2（会话卡）**：「这个也是**内部有阴影，外部阴影弱**」

**关键线索是"8 边形"**：那是**平台投影对圆角/圆形的 N 边形近似**被玻璃透上来看到的结果
⇒ 说明平台投影同样不满足"只在外侧"，而且它**在内部还有轮廓**。

**定稿架构（Java `Ui.ShadowedDrawable` 的忠实移植，但用 Compose 能表达的方式）**：
```
drawWithCache {
  ① 建一张比节点大 2×pad 的位图，把「形状（下移 dy）」填上投影色
  ② 可分箱式模糊（与 Java 侧 Ui.boxBlur 同一算法，纯 Kotlin 移植）
  onDrawBehind {
    ③ nc.clipOutPath(形状)   ← 绘制裁剪，**不需要离屏层** ⇒ 前面几版的矛盾全部消失
    ④ 把模糊位图画到形状之外
  }
}
```
**为什么这版能同时成立**：`clipPath/clipOutPath` 是**绘制裁剪**（不是层裁剪）⇒
① 位图可以画到节点外（不会被矩形切断）；② 形状内部**一点都不画**（不是靠 alpha 压，是根本画不进去）。

**实测（模拟器）**：
| 检查 | 结果 |
|---|---|
| 跟随形状 | ✅ 圆钮圆形、卡片圆角（`202`/`203`） |
| 不被节点裁 | ✅ 投影完整铺到形状外 |
| **内部零影响** | ✅ 卡片内部**中段 244.6 / 下段 243.8（差 0.8）**；圆钮内部干净（无 8 边形、无透灰） |
| 方向 | ✅ 位图整体下移 `dy = pad×0.42`（左上受光 ⇒ 影子偏下） |

**取证**：`evidence/v3260/201`（整屏）、`202`（圆钮）、`203`（卡片）。

> **五轮试错的最终结论**（详见函数头注释的表）：Compose 自带的三种投影
> （`shadow` / `dropShadow` / `dropShadow`+离屏层）**都无法**同时满足
> 「跟随形状 + 不被节点裁 + 内部零影响」—— 只有**自绘位图 + 绘制期裁剪**这条路走得通。

### 2.4.5 用户第 6 轮：长条阴影再小 + 过渡更自然 + **按压"缩小且两层"复发**
用户原话：「看着还行，**长条对话的阴影可以再小点**，然后**过渡再自然点**，然后**按下去时候又出现了刚才那种缩小且两层的情况**。」

| 问题 | 处置 |
|---|---|
| 长条（会话卡）阴影偏大 | `GlassShadow.CardPad` **10dp → 7dp** |
| 过渡不够自然 | 模糊半径系数 **0.55 → 0.9**（箱式模糊半径随 pad 放大 ⇒ 边缘过渡更柔） |
| **按压时"缩小 + 两层"复发** | 根因：`glassTap` 里是 `graphicsLayer{scale}`，**排在它外面的阴影不会跟着缩放** ⇒ 按下时元素缩小、阴影留在原尺寸 = 两层。**修法：把 `glassTap` 挪到阴影之前**（5 个调用点全改） |

**模序新纪律（V3.26 起）**：`… → glassTap{…} → glassShadow(shape) → clip/background/border`
（`glassTap` 先 ⇒ 阴影在缩放层**里面**，跟着一起缩放；且仍满足 V3.21"glassTap 排在 clip/background 之前"）。
**已改 5 处**：抽屉圆钮、会话卡、对话页圆钮、能力 chip、子智能体胶囊。

**取证**：常态 `evidence/v3260/210`（+ 裁剪 `21n_btn_normal` / `21n_card_normal`）、
**强制按下态** `211`（+ `21p_btn_pressed` / `21p_card_pressed`，`--ez glass_force_press true`）⇒ 阴影随元素一起缩小，无第二层。

## 5. #5 设置页三件事（分区折叠 / 配色即时 / 点内部按钮不跳顶）

| 各板块可以折叠，目前显示过多 | `SectionCard` 永远展开（4 个分区全铺开） |
| **配色调整不立马变化** | `GlassSettingsActivity.rebuild()` 用的是 **`recreate()`（重建整个 Activity）** ⇒ 配色要"重建后才生效" |
| **点外观内部按钮画面会弹到顶部** | ① `recreate()` 必然丢滚动位置；② 即使不重建，调用方用 **`key(state.themeRev) { … }`** 强制重建子树 ⇒ **滚动节点被重建**，重建首帧内容高度为 0 ⇒ `ScrollState.value` 被夹到 0 ⇒ 偏移丢失（Compose 经典坑） |

### 5.2 改法
1. **分区可折叠**：`SectionCard(backdrop, title, open, onToggle)` —— 标题行可点、带 ▸/▾；**默认全部收起**（一屏看完 4 个分区）。折叠状态放 `GlassSettingsState.sectionOpen`（`mutableStateMapOf`，在 state 里 ⇒ 主题重建也不丢）。
2. **配色即时**：`rebuild()` 从 `recreate()` 改成 **`state.bumpTheme()`**（就地重组，不重启 Activity）。
3. **不跳顶**：
   - `GlassAppTheme` 增加 **`themeRev` 参数**并在体内读取 ⇒ 换主题时**本组件就地重组**（重建 colorScheme），
   - **去掉全部 5 处 `key(state.themeRev) { … }`**（各屏本来自己就读 `themeRev`，那层 key 是多余的，而且正是丢滚动偏移的元凶），
   - 设置页滚动状态建在 `key` 之外（`SettingsSlite` 里 `rememberScrollState()` 传给 `GlassSettingsScreen(scrollState = …)`）。

## 6. 用户追加（同日·第 7 轮）：会话卡再压扁 + 间距留阴影 + 设置分区「名字进胶囊」

### 6.1 会话卡：更扁 + 间距拉开（两条要求有张力，算术摆明）
- 行内上下内边距 **8dp → 6dp**（卡片更扁）
- 卡**间距 2dp → 8dp**（把阴影空间留出来：卡片阴影是"只画在形状之外"的模糊投影，
  外扩 7dp + 下移 ~3dp ⇒ 间距 < ~10dp 时影子会被**下一张卡盖住**，看着像没阴影）

- 实测：`evidence/v3260/273`（卡片更薄、间距更大、**阴影可见**）；节距由 uiautomator 量得 205px。
