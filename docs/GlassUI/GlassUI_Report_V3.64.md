# GlassUI 迭代报告 V3.64 | 2026-10-11（"切换对话不停加载、没法用"：A/B 定因 + 已修 + 复验）

> **触发**：用户「切换对话，还是不停的加载对话内容，没法直接使用，你在检查下」。

---

## 1. A/B 定因（用网关诊断日志量化，不猜）

| 状态 | 25 秒内网关 `snapshot` 请求增量 |
|---|---|
| **App 关闭** | **0** ✓ |
| **App 开着** | **333** ✗，其中最近 300 行里 **281 行都是同一个会话**（`session-4ff114d8…`） |
⇒ **同一个会话被约 11 次/秒地反复请求**；而 `onSnapshot()` **每次都 `items.clear()` + 重建整列**
⇒ 界面一直在重建 = 用户看到的"不停加载、没法用" ✓。
（顺带排除：这一版已把**我的自动翻页关掉**，仍然猛拉 ⇒ **不是自动翻页** ✓。）

## 2. 修复

| # | 改动 | 说明 |
|---|---|---|
| ① | **同内容快照去重** | `onSnapshot` 开头算指纹（`会话号 + cursor + 事件条数 + 末条 seq`），**与上次一致且列表非空 ⇒ 直接 return**，不再 `clear()+重建` ⇒ 界面不再被反复重刷 |
| ② | 自动翻页**只在真正换会话时重置** | 原来**每次快照都 `autoPageCount = 0`**，而"每页历史回来又触发快照"⇒ 计数被反复清零 ⇒ 永远拉不完 |
| ③ | 自动翻页**暂时关闭**（`AUTO_PAGE_MAX = 0`） | 先保证"能直接使用"；等请求风暴治干净再谈"自动补齐" |
| ④ | 「正在加载更早…」在自动翻页时不显示 | 用户要的"默默加载" |

## 4. ⚠️ 仍留一条（如实交代）

**那 ~11 次/秒的请求本身还在** ✗——本轮治的是它造成的**界面重刷**（用户可感知的那一半）；
请求来自 App 侧的标题队列/订阅路径（网关 `sessionSnapshot` 日志能证），**下一步**：
给网关再加一行"调用方"标记（title / history / subscribe）⇒ 定位后把无意义的轮询停掉
（对省电与流量也有意义）。
