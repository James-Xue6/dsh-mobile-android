# GlassUI 迭代报告 V3.113 | 2026-10-12（"跑到对话界面 + 成透明的了"根因与修复）

> **触发**：用户「**粘贴配对串**点开**跑到对话界面了**，不是规范的玻璃弹窗**成透明的了**；
> 首页**修改名称**也**不弹出、跑到对话位置**弹出了」。

---

## 1. 根因（两条症状同一个病）

玻璃 sheet 的渲染器**只有两处**，而且都有前提：

| 渲染器 | 何时有效 |
|---|---|
| 聊天页内那一个（`GlassChatScreen` 的 `GlassSheetOverlay`）| **聊天页被组合时**才有效 |
| 抽屉里的独立全屏宿主（`createGlassSheetHost`）| 常驻，但它**采样的是某个取样层**，层无效时面板就是**透明**的 |

⇒ 你是在**设置页/设备页**点这两个弹窗的：
1. 聊天页那时**没有被组合** ⇒ 它那份渲染器不工作；
2. 只剩**抽屉那个全屏宿主**在用（它是**整屏**的 ⇒ 盖住一切，所以看起来"跑到对话界面" ✗）；
3. 而它拿到的取样层是**空的/过期的**（我在 `SideEffect` 里设了全局引用，却**没有在销毁时清空** ✗）
   ⇒ 面板采样一个没人绘制的层 ⇒ **透明** ✓✗

## 2. 修复（三条，都是"宁可降级也不要画坏"）

| 改动 | 作用 |
|---|---|
| `GlassChatScreen`：`DisposableEffect` 里 **`onDispose` 清空** `GlassChatBackdrop.layer` | 聊天页切走后，**过期的层不会再被使用** ✓ |
| `GlassSessionList.createGlassSheetHost`：**只在聊天页无法自己渲染时**（`GlassChatBackdrop.layer == null`）接管；且**必须拿到有效层**（抽屉那层），拿不到就**什么都不画** | 消除"同一状态被渲染两次"与"空层采样⇒透明" ✓ |
| `GlassChatView`：给 `showSheetList / showSheetForm / showSheetConfirm` 加**统一前置守卫** `sheetBackdropReady()`（两层都无效 ⇒ 返回 false）| 调用方**回退旧弹窗** ⇒ 弹一个**实心旧对话框**，也**绝不再弹透明玻璃** ✓ |
