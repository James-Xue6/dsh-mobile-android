## 2. ②流式吐字一顿一顿：**机制找到了**（不是玻璃的问题）

`GlassChatView.setItems()` 被 `MainActivity` 在**每一帧数据到来时**调用（流式时每个 token 一次），而它里面：

```java
state.setItems(new ArrayList<>(items));   // ← 立刻一次全表状态更新（重组 + 重绘）
pullVisibleLater();                        // ← 再 postDelayed(120ms) 拉"过滤后可见行"，**又**一次
```

⇒ 每个 token **两次整表状态更新**；而且那个 120ms 延时任务**每次都新 post 一个、从不取消旧的**
⇒ 吐字期间会**堆积一串待执行任务**，每个再各写一次状态。这与你描述的「吐字一顿一顿 / 卡卡的」完全吻合。

**修法**（只动这一个文件，行为不变）：
- 立刻那次镜像改成**节流**：`MIRROR_THROTTLE_MS = 70ms`，**末尾必发**（不丢最后一帧）；
- 延时拉取改成**只保留一个待执行任务**（`removeCallbacks` 后再 post）；
- 过滤结果到达时**立刻上屏**，不走节流（否则吐字末尾慢一拍）。

⇒ 更新频率从"每 token"降到"**最多 ~14 次/秒**"，且不再堆积。

> ⚠️ 诚实标记：这条**我只验证到"机制已修 + 编译通过 + 真机不崩"**。
> 要给出数字，需要在**受控流式**下采真机 `gfxinfo` —— 我这边造不出受控的流式输入，得靠你实际用一次。
